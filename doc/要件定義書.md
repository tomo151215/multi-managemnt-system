## 1. 目的・背景・範囲

### 1.1 目的

宮崎マルチメディア専門学校の学籍・履修・時間割・出欠・成績・資格・就職活動を一元的に管理し、教職員の作業負担を軽減するとともに、生徒への情報提供と教育・就職支援の品質を高める。

### 1.2 背景・課題

現状は手作業やExcel等の個別資料に情報が分散し、二重入力・情報の不整合・確認作業の属人化が発生している。時間割と履修の変更を出欠や成績に正しく反映すること、進級の判断に使う実績と予測を区別すること、就職活動の全過程を継続して確認できることが必要である。

### 1.3 達成目標

| ID | 目標 | 達成条件 |
|---|---|---|
| G-01 | 情報の一元化 | 権限を持つ利用者が各領域の情報を同一システム上で登録・更新・参照できる |
| G-02 | 入力負担の低減 | 通常日の時間割の自動適用、出欠候補の継承、座席表による差分操作を利用できる |
| G-03 | 記録の整合性 | 生徒・科目・年度・時限を正しく区別し、禁止重複や無効な入力を保存できない |
| G-04 | 生徒の自己確認 | 本人の履修・時間割・出欠・成績・資格・就職状況を閲覧できる |
| G-05 | 進級支援 | 科目別実績・概算予測・達成可能性を根拠付きで確認できる |
| G-06 | 過年度の追跡 | 年度・所属の変更後も過去の所属・学習・就職記録を参照できる |

### 1.4 対象機能

1. 認証・アカウント・権限・ダッシュボード
2. 年度・学期・学科・コース・クラス・学籍・担任管理
3. 科目・履修・年間日程・週時間割・日別変更・教室管理
4. 座席表・席替え・出欠記録・進級判断支援・出席帳票
5. 学期別評価点・年間成績・成績統計・成績帳票
6. 資格受験・合否・資格取得・有効期限
7. 企業・応募・選考・就活状況・学内会場予約・就職統計・連絡
8. 履歴書のPDF出力・証明書の申請

### 1.5 対象外

- 試験ごとの得点や平常点の内訳の保存・集計（学期別評価点のみ管理）
- 進級・卒業の最終決定の自動化
- 特定日のみの教員変更・教室変更・履修者変更（別科目への振替で対応）
- **確定出欠が存在する授業の時間割変更（例外操作を含め禁止）**
- 出欠訂正前の値を追跡する専用履歴の表示・管理
- 未登録出欠の時刻による自動確定・自動保存
- 資格試験の受験予定の管理
- 年度・学期途中の入学・編入（途中入学・編入自体を扱わない）
- 学期・年度境界以外での休学開始・復学
- 休学期間中の出欠・成績・就職活動記録の新規登録
- 学校行事以外の任意の手動コマ換算
- 生徒による資格記録の直接登録・更新
- 生徒の希望勤務地の保持
- 証明書申請の送信履歴・受理ステータスの管理、証明書そのものの自動発行
- 資格証明書ファイルの保存、独自監査ログ管理画面

**変更管理**：本書に定めない機能を追加する場合は、対象範囲と関連要件への影響を確認し、要件変更として承認する。

## 2. 用語・業務上の共通原則

### 2.1 用語

| 用語 | 意味 |
|---|---|
| 生徒 | 在籍する学習者。原則「学生」と混用しない |
| 教職員 | 教員・その他職員・外部講師を含む学校側の利用者。担任・科目担当などの職務によらず共通の操作権限を持つ |
| 担任 | クラスの朝HR、出欠の事前連絡・支援等を主に受け持つ教員。操作権限の区分ではない |
| 科目担当教員 | 担当授業の出欠確認や成績評価を主に受け持つ教員。操作権限の区分ではない |
| 年度 | 毎年4月1日から翌年3月31日までの学校年度 |
| 学期 | 年度内の期間。前期・後期の2学期とする |
| 学科／コース | 所属区分。コースは学科に属する |
| クラス | 担任が受け持つ生徒集団。複数コースの生徒が所属し得る |
| 教育課程 | 年度・学期・学科・コース・学年に対応する教育内容の区分 |
| 履修科目 | 教育課程の必修科目または生徒ごとに登録された選択科目 |
| 週時間割テンプレート | 通常日の曜日・時限・科目・教員・教室を示す基準 |
| 日別時間割変更 | 特定日の特定時限について基準から変更する操作・設定 |
| 授業実施枠 | 特定日時の授業または朝HRについて出欠確認対象を識別する業務単位 |
| 事前出欠情報 | 授業前の欠席・遅刻等の連絡内容。実施後の出欠確定記録とは異なる |
| 出欠候補 | 当該授業の初期表示用に継承した未確定状態。候補表示だけでは実績とならない |
| 確定出欠 | 教職員が当該授業について確認し、保存した出欠実績 |
| 総授業コマ数 | 進級対象科目に実施実績として算入するコマ数（整数） |
| 認定出席コマ数 | 生徒・科目ごとに出席・公欠等として認定するコマ数（整数） |
| 年間評価 | 前後期または片学期の評価点から確定するA～Dの区分 |
| 選考種別 | 説明会、書類選考、筆記試験、面接など、選考の内容 |
| 選考の実施状態 | 予定・実施済み等の進行状態。選考結果と区別する |
| 個別結果 | 未判明・通過・不通過・選考対象外のいずれか |
| 応募全体の状態 | 検討中・応募済み・選考中・内々定・内定・不合格・辞退。中止事由が発生した応募は中止を表示。システムが経過から自動決定する |
| 現在の内定数 | 現時点で有効な内定・内々定の件数（辞退済みを除く） |
| 累計内定数 | 過去に取得した内定・内々定の累計（後に辞退しても取得実績を含む） |

### 2.2 共通業務ルール

- 対象年度・学期・科目・生徒・時限を区別して業務情報を表示する。
- 予定・事前連絡・候補・確認済み実績・概算予測・最終判断を混同しない。
- 年度内の在籍状態と休学状態を区別し、休学中は新しい出欠・成績・就活実績を登録しない。休学前の記録は保持する。
- **確定済み出欠が1件でもある授業の時間割編集は、教職員全員に対して禁止する。出欠そのものの訂正は禁止しない。**
- 必須項目の未入力は、0点・欠席・不合格などの確定値とは区別する。
- 正当な合同授業を除き、同一人物・教員・教室が競合する禁止重複は登録時に拒否し、理由を示す。
- 生徒が他人の情報へ直接アクセスすることを禁止する。画面以外のURL等からの操作にも同じ権限を適用する。
- 過年度の記録を不用意に上書きせず、対象年度の記録として確認可能にする。
- 学校の運用上の判断とシステムの算出・表示を区別し、自動計算を進級・合否等の最終決定とみなさない。

## 3. 利用者・権限

### 3.1 利用者区分と業務上の担当

システムの**操作権限は「生徒」と「教職員」の2区分**を基本とする。教職員には担任、科目担当教員、その他教職員、外部講師を含め、**4者のアクセス可能な画面・情報・登録・編集・確定・訂正・管理操作の範囲は同じ**とする。専用の学校管理者区分、担任限定権限、科目担当限定権限、外部講師限定権限を設けない。

| 利用者・担当 | 主な業務（操作権限の違いではない） |
|---|---|
| 生徒 | 本人の教務情報・資格・就活の閲覧、本人の就活情報の登録・更新、校内選考会場予約、履歴書PDF出力、証明書の申請 |
| 担任 | 通常は朝HRの出欠確認、事前連絡の取りまとめ、家庭への連絡、進級支援、本人確認を伴うパスワード再設定を担当 |
| 科目担当教員 | 通常は担当授業の出欠確認・確定、担当科目の評価点の判定・入力・確定を担当 |
| その他教職員 | 通常は学籍・教育課程・時間割・年間日程・就活支援などの校務を担当 |
| 外部講師 | 通常は担当授業の出欠・成績等の業務を担当。教職員アカウントでは他の教職員と同一の操作権限を持つ |

- **担当者とは日常業務を実施する人を指し、認可条件ではない。** 担当クラスや担当科目が異なっても、教職員アカウントであれば対象の生徒・授業・成績等を閲覧・登録・確定・訂正できる。
- 担任・科目担当教員等の割当と効力発生日は、時間割・ダッシュボード・業務上の担当表示に利用する。割当の変更によって教職員の操作権限そのものは増減しない。
- **教職員全員**が全生徒の教務情報と、資格・就職活動情報を参照でき、時間割・学籍・履修・年間日程・座席表・出欠・成績・資格・帳票等の教職員向け機能を共通して利用できる。
- 例えば、朝HR・事前出欠の登録は通常担任、授業出欠の確定は通常その授業の担当教員、学期別評価点の確定は通常科目担当教員が行う。ただし、**システム上は他の教職員が同じ操作を行うことも許可する**。
- パスワード再設定は本人確認を条件とし、通常は担任が対応するが、他の教職員も同じ再設定機能を使用できる。
- アカウントの新規発行・利用停止は全教職員が行える。退職・契約終了した教職員は退職処理の登録時点で利用停止する。
- 生徒は本人の情報のみ参照・操作できる。生徒による出欠・成績・資格記録の直接編集、他者の情報の閲覧・更新、学校運営情報の管理は認めない。
- **業務状態に基づく制限は全教職員に共通して適用**する。例えば、確定出欠が1件でもある授業の時間割変更、学期開始後の選択科目の変更、休学中の実績作成、予約開始後の変更・取消は禁止する。肩書きによる例外を設けない。

### 3.2 操作権限の一覧

| 対象操作 | 生徒 | 教職員（担任・科目担当・その他教職員・外部講師に共通） | 主な業務担当（アクセス制限ではない） |
|---|---|---|---|
| 本人の教務・資格・就活情報の閲覧 | 本人分○ | 全生徒分○ | 生徒本人／教職員 |
| 年度・学籍・教育課程・履修・時間割・年間日程・座席表の管理 | × | ○ | 校務の担当者 |
| 朝HR・授業前の事前出欠情報の登録・訂正 | × | ○ | 通常は担任 |
| 授業・HRの出欠確認、一括確定、過去の出欠訂正 | × | 全授業で○ | 通常は当該授業の担当教員または担任 |
| 学期別評価点の入力・確定・公開後訂正 | × | 全科目で○ | 通常は科目担当教員 |
| 資格の受験・取得記録の登録・更新 | × | ○ | 通常は生徒の報告を受けた教職員 |
| 本人の就職活動状況の入力・更新 | 本人分○ | ―（教職員向け支援・参照機能とは区別） | 生徒本人 |
| 全生徒の就活情報閲覧・支援・Gmail連絡作成 | × | ○ | 就活支援を行う教職員 |
| 校内選考会場の空き確認・予約 | ○ | ○ | 予約する生徒・教職員 |
| 出欠・成績PDFの出力 | × | ○ | 通常は担任・科目担当教員等 |
| 出席PDFの学校連絡事項の入力 | × | ○ | 通常は担任 |
| 本人確認後のパスワード再設定 | × | ○ | 通常は担任 |
| アカウントの発行・停止 | × | ○ | アカウント業務を行う教職員 |
| 履歴書PDFの出力 | 本人分○ | 全生徒分○ | 生徒本人・教職員 |

**運用上の担当者と操作権限は独立**しており、担当者情報によるメニュー非表示や操作拒否を行わない。ただし、生徒本人への閲覧範囲制限、本人確認、必要項目の検証、予約の重複検査、成績の確定状態等、各機能の業務条件は維持する。

## 4. 業務フロー

### 4.1 年度開始・年度更新

1. 教職員が次年度・学期、学科・コース・学年・教育課程を設定する。
2. 教職員が**次年度のクラス所属を手動登録**し、担任と担当教員を設定する。旧年度の所属を上書き消去しない。
3. 必修・選択科目を登録し、教職員が生徒別に選択科目を履修登録する。
4. 学校共通の年間日程と学期別の週時間割テンプレートを用意する。
5. 教室・座席表・座席割当を準備する。
6. 時間割の禁止重複を確認し、生徒・教員が対象年度の内容を参照できるようにする。
7. 留年、休学、退学、転科、転コース等の異動は事前登録し、指定した学期・年度境界で反映する。**途中入学・編入は扱わない。休学中は新規の出欠・成績・就活記録を作らない**。過去の履歴は保持し、卒業・退学の効力発生日に生徒アカウントを停止する。

### 4.2 毎日の出席確認

1. 学校共通の年間日程・週時間割・日別変更を反映した当日の授業を表示する。
2. 通常は担任が連絡を受けて**事前出欠情報**として登録する。ほかの教職員が連絡を受けた場合は担任への伝達を基本とするが、登録操作自体は全教職員に許可する。授業確定実績にはしない。
3. 通常は担任が朝HRの共通座席表を用いて出欠を確認・確定する。ほかの教職員による操作も許可する。HRはコース別に独立して扱う。
4. 通常は授業担当教員が当該授業を開き、保存済み確定出欠・事前情報・前時限等の候補を確認する。担当外の教職員も同じ操作ができる。
5. 教職員が実際の出欠に合わせて変更し、**対象者全員の出欠を一括して手動確定・保存**する。この確定をもって授業を実施済みと扱う。
6. 授業途中の入室・早退が判明した場合、確定出欠を手動で再保存する。
7. 保存済み結果を次時限の候補表示と、実施済みコマ数集計に反映する。
8. 登録忘れ・誤入力があれば、教職員が過去の対象授業を指定して訂正する。

### 4.3 学期末・年度末

1. 通常は科目担当教員が学期別評価点を判定・登録し、確認後に確定する。担当外の教職員も登録・確定操作を行える。
2. **確定した時点で生徒が閲覧できる**。未確定は0点と区別する。
3. 必要な学期の評価が揃えば年間平均点と年間評価A～Dを自動算出する。
4. 教職員が科目別出席コマ数、進級基準、年度末概算予測と成績を確認する。
5. 全授業終了後、実際の総授業コマ数と認定出席コマ数で基準達成の有無を判定する。
6. **進級の最終判断は教員が行う**。システムの表示だけで進級・卒業を自動確定しない。
7. 教職員が次年度の所属・教育課程を手動登録する。

### 4.4 資格取得

1. 生徒が受験結果を教職員に報告する。
2. 報告を受けた教職員が結果を確認する。合格・取得の場合は合格証・認定証等で確認する。
3. 教職員が受験結果（合格・不合格・結果待ち）、受験回、取得状況、有効期限等を登録・更新する。
4. 生徒本人は結果と資格取得状況を確認する。

### 4.5 就職活動・教室予約

1. 生徒が企業・応募・選考過程・予定を登録する。複数企業と同一企業への再応募を許可する。
2. 面接等の日程・結果が未定でも予定を入力できる。
3. 会場が学校の場合、開始・終了時刻を指定して空いている部屋を予約する。重複は不可。
4. 生徒が選考の予定／実施状態および個別結果を更新し、システムが応募全体の状態を自動更新する。矛盾する値は保存しない。未定日程の選考は生徒指定の順番で表示する。
5. 辞退した場合は当該応募の未実施の予定選考を削除し、実施済み選考は残す。削除対象の選考に結び付く**未使用の校内教室予約も自動で取り消す**。
6. 教職員は進捗・統計を確認し、連絡機能で生徒を支援する。メールはシステムがGmailの作成画面に宛先・件名・本文を引き渡し、教職員がGmail上で送信する。
7. 生徒は履歴書の内容を保存・再編集してPDFを出力する。証明書の申請情報は確認画面で再確認してから、Gmail作成画面に引き渡し、本人が送信する。メール送信済みの状態や申請履歴はシステムで管理しない。

## 5. 認証・共通画面

### 5.1 認証・パスワード

- **AUTH-01**　学校配布メールアドレスとパスワードでログインする。生徒のID例：`mmc11111@student.multi-m.ac.jp`、教職員のID例：`mmc11111@teacher.multi-m.ac.jp`

- **AUTH-02**　1人につき1アカウントとし、各アカウントは生徒または教職員のどちらか一方に対応する

- **AUTH-06**　成功時は生徒用または教職員用ダッシュボードへ遷移する

- **AUTH-07**　認証失敗時はID不存在とパスワード誤りを区別せず同じエラーを表示する

- **AUTH-08**　無操作20分でセッションを失効させ、再ログインを求める

- **AUTH-09**　ログイン後は現行パスワード・新パスワード・確認入力で変更する

- **AUTH-10**　ログイン画面の再設定リンクでは通常の連絡先である担任への相談を案内する。**本人確認後、教職員が本人指定の新パスワードに再設定できる**。担当の違いによるアクセス制限は設けない。入力された秘密情報はログ・通知・画面で表示しない

- **AUTH-11**　URL等からの権限外アクセス・操作や、生徒による他者の情報閲覧を拒否する

- **AUTH-12**　同一アカウントのログインを**5回連続失敗**した場合、**15分間ログインを制限**する。失敗理由を区別して表示しない

- **AUTH-13**　教職員によるアカウント発行・停止と、担当クラス・科目変更の効力発生日に応じた担当表示の切替を行う。教職員の共通操作権限は変更しない

### 5.2 共通UI・一覧

- **COM-01**　生徒・教職員のダッシュボードを提供し、各自の業務・参照機能へ遷移できる

- **COM-02**　日・週・月の時間割・日程表示を提供し、対象年度・日付を明示する

- **COM-03**　一覧画面は領域ごとに指定された検索・絞り込み・並べ替えに対応する

- **COM-04**　保存前に必須値・数値範囲・禁止重複を検査し、失敗時は理由を表示する

- **COM-05**　未登録・予定・事前情報・確定・予測を表示上で区別する

- **COM-06**　ライトモード・ダークモード双方で可読性と操作性を維持する

- **COM-07**　教職員・生徒のPCとスマートフォンに対応する

- **COM-08**　通常画面操作は95%以上を3秒以内に完了する目標とし、帳票出力・一括処理はこの計測対象から除く

## 6. 学籍・教育課程・履修

### 6.1 学籍・クラス

- **ADM-01**　学科・コースを登録・編集・一覧表示する

- **ADM-02**　**年度を4月1日〜翌3月31日**とし、前期／後期・学年・教育課程を管理する

- **ADM-03**　年度・学期・学科・コース・学年ごとの教育課程を区別する

- **ADM-04**　クラスを登録・編集し、生徒の年度別所属・過去の所属を確認できる

- **ADM-05**　担任を割り当て、担任交代の履歴を確認できる

- **ADM-06**　生徒・教職員の基本情報を管理する

- **ADM-07**　休学・退学・転科・転コース等の異動を**事前登録**し、指定された次の年度・学期境界から反映する。休学中は新しい出欠・成績・就活情報を登録せず、休学前の記録は保持する

- **ADM-08**　次年度の所属は教職員が手動で登録し、進級・留年等の結果を反映できる

- **ADM-09**　**年度・学期の途中入学・編入は取り扱わない**。年度・学期境界での学籍異動のみ管理する

**業務ルール**

- 生徒の同一時点の所属クラスは1つだけとする。
- **同じ年度の同じコースの生徒は複数のクラスに分割しない**。
- 一つのクラスに複数のコースの生徒が所属してよい。
- クラスにはその時点で担任1人を割り当て、担任の交代履歴を確認できる。
- 担任を受け持たない教科担当教員や外部講師がいてもよい。
- 教育課程や科目の配置は年度をまたいで混同しない。
- 学籍異動は学期・年度の区切りから反映する。途中入学・編入は扱わず、**休学期間中は出欠・成績・就活の新規登録を禁止**する。過去記録は保持する。
- 卒業・退学の効力が生じた時点で当該生徒のアカウントを停止する。

### 6.2 履修科目

- **ENR-01**　科目名等の基本情報を登録・編集する

- **ENR-02**　教育課程ごとに必修科目と選択科目を設定する

- **ENR-03**　必修科目を該当教育課程の生徒の履修対象に含める

- **ENR-04**　**教職員のみ**が生徒別の選択科目を登録・変更できる。変更・取消は**原則として学期開始前のみ**許可し、開始後は不可

- **ENR-05**　生徒は本人の履修一覧、教職員は対象の履修一覧を閲覧できる

- **ENR-06**　生徒の時間割には本人が履修する科目だけを表示する

- **ENR-07**　履修状態を、授業での出欠対象者、成績管理の対象者、時間割の重複判定へ反映する

**運用ルール**：同一科目の履修者は同じ曜日・時限の授業を受ける。選択科目により同時刻に複数の授業が存在しても、**同一生徒が同時刻に複数科目を履修する競合**は許可しない。選択科目の変更・取消は学期開始前に限定し、**変更前に確定した出欠・成績は消去しない**。学期開始後の変更・取消は認めない。

## 7. 年間日程・時間割

### 7.1 年間日程

- **CAL-01**　年間日程は原則として学校全体で共通管理する

- **CAL-02**　授業日・休日・休校・試験・学校行事・長期休暇等を登録・編集する

- **CAL-03**　期間指定の一括登録と単日編集を行える

- **CAL-04**　日・週・月のカレンダーに予定を表示する

- **CAL-05**　予定を特定の日・時限へ組み込む際、予定自体を再入力せず対象時限だけ指定できる

- **CAL-06**　時限に対応しない年間予定も登録・表示できる

- **CAL-07**　学科・コース・学年の個別の授業差異は日別時間割変更で調整する

- **CAL-08**　年間日程と日別時間割変更の内容が**競合する登録を禁止**し、教職員に修正を求める

### 7.2 週時間割テンプレート

- **TT-01**　教育課程ごとに週時間割テンプレートを少なくとも1つ設定する

- **TT-02**　前期・後期等で基準が異なる場合、同一教育課程に複数テンプレートを設定できる

- **TT-03**　曜日・時限ごとに科目・担当教員1人・教室を設定する

- **TT-04**　授業のない空欄時限を許容する

- **TT-05**　変更のない通常日は毎日登録せず、対象期間のテンプレートを自動適用する

- **TT-06**　登録・変更時に履修者・教員・教室の禁止重複を検査する

- **TT-07**　選択科目を同時刻に並行配置できる。ただし履修者の重複や不正な教室競合は不可

- **TT-08**　教員は全コースの時間割と自分の担当授業を参照し、該当授業の出欠確認へ遷移できる

- **TT-09**　生徒は自身の履修授業のみ参照する

- **TT-10**　日・週・月表示に対応し、月表示は年間日程を中心に示して時限ごとの授業詳細を表示しない

### 7.3 日別時間割変更

- **TTD-01**　特定の日付・時限に限り、基準科目を別科目へ振り替えられる

- **TTD-02**　通常は授業のない時限に新たな授業を追加できる

- **TTD-03**　日別変更によって元の週テンプレートは変更しない

- **TTD-04**　振替先は当該教育課程の週時間割に登録済みの科目から選ぶ

- **TTD-05**　振替先科目に定められた担当教員・教室・履修対象者を用いる

- **TTD-06**　特定時限だけの担当教員・教室・履修者の差し替えは提供しない

- **TTD-07**　教員不在時は担当教員の一時変更ではなく、別科目への振替で対応する

- **TTD-08**　同じ教育課程・日時・時限の同一授業を二重登録させない

- **TTD-09**　**確定出欠が1件でも保存された授業の時間割変更は、時期や理由を問わずすべて禁止する**。教職員・運用担当者の例外操作も設けない

- **TTD-10**　週テンプレート・年間日程・日別変更の編集によって、**確定出欠のある既存の授業の科目・日時・教員・教室等が結果として変わる場合も、その変更を禁止**する

### 7.4 コース別の授業・合同授業

- **HRと通常授業の出欠対象は原則としてコースごとに独立**して扱う。同室・同教員で授業が並行しても、コース別の出欠記録と集計をまとめない。
- **同一日**の異なるコースの授業で、次の**すべてが一致**した場合に限り、同じ教員・教室の重複を合同授業として**自動的に許可**する。
  1. **同じ科目**であること
  2. **担当教員が同じ**であること
  3. **教室が同じ**であること
  4. **授業開始時刻と終了時刻の双方が完全一致**すること
- いずれかが一致しない授業で教員や教室が同じ時間帯に重複する場合は、禁止重複として登録を拒否する。開始終了時刻の一部のみの重複は合同授業として認めない。
- 同じ日時・同一コースの授業を二重登録することは、上記の例外に含まれない。同じ生徒に複数の授業を割り当てることも禁止する。
- **同一科目**とは学校の科目として同じものを指す。科目名が異なる授業は内容が類似していても合同授業としない。別コースの合同授業には、同一担当教員・同一教室・開始時刻と終了時刻の完全一致も必要である。

### 7.5 授業実施枠・特殊日程の基本ルール

- 実際の授業・HRを日付・時限・コース等に基づき独立した出欠確認対象として扱う。
- 特定日の実施内容は、年間日程・基準テンプレート・矛盾なく登録された日別変更を反映して表示する。
- 休講・補講を独立した運用区分として扱わず、別の授業を行う場合は時間割を振り替え、通常の授業実績として集計する。
- 休校は休日相当として扱い、授業実績に算入しない。将来の振替授業が別日に実施された場合、その実施分のみ算入する。
- 科目ごとの年度総授業コマ数は年度当初に固定せず、実施済みの授業実績から集計する。

## 8. 教室・座席表・席替え

### 8.1 基本ルール

- 座席表は**クラス共通を基本**とし、コース別授業・選択授業では個別座席表を設定できる。
- 同じクラスに属する複数コースが同一教室で朝HRを受ける場合はクラス共通の座席表を利用する。
- コース別の移動教室・選択授業では、その授業に適した座席表を利用する。
- **各授業に適用する座席表を事前に指定**する。出欠画面では授業に指定された座席表を自動的に表示し、教職員がその場で別の座席表へ切り替える操作は認めない。
- **適用座席表が指定・登録されていない授業は出欠確認画面を開けない**。教職員が適用する座席表を用意してから利用する。別の共通座席表へ自動的に代用しない。
- 合同授業はコース別の出欠を維持しつつ、同じ教室の座席位置に別の生徒が重複表示されないようにする。

### 8.2 機能要件

- **SEAT-01**　クラス共通・コース別・選択授業用の座席表を登録・利用できる

- **SEAT-02**　行数・列数を指定して単純な格子状の座席を生成する

- **SEAT-03**　配置のない位置、誰も座っていない空席を表示できる

- **SEAT-04**　通路幅・机間隔・不規則な実物寸法は扱わない

- **SEAT-05**　各生徒を座席へ割り当て、席替えを行える

- **SEAT-06**　座席割当の開始・終了時点から過去の配置を確認できる

- **SEAT-07**　同一時点・同一座席への複数生徒の割当を禁止する

- **SEAT-08**　同じ授業について1人の生徒が複数席に表示されないようにする

- **SEAT-09**　同一教室の合同授業で各コースの生徒の席が重ならないよう検査する

- **SEAT-10**　授業ごとに座席表を事前指定し、出欠画面ではその座席表を自動表示する。授業時の選択・変更は許可しない

- **SEAT-11**　適用座席表が未登録・未指定の場合は出欠確認画面を開けず、座席表を用意するよう案内する

## 9. 出席管理

### 9.1 出欠区分と認定コマ数

| 出欠区分 | 定義 | 認定出席コマ |
|---|---|---:|
| 出席 | 授業開始から20分未満に参加し、途中退室せず受講 | 1 |
| 遅刻 | 授業開始から20分以上経過して参加し、途中退室しなかった | 0 |
| 欠席 | 当該授業を受講しなかった | 0 |
| 早退 | 授業途中で退室・下校した。遅刻と重なった場合もこちらを優先 | 0 |
| 公欠 | 学校が認める事由により受講できなかったが出席と同等に扱う | 1 |

- 20分未満と20分以上を境界とする。**開始20分ちょうどは遅刻**となる。
- 遅刻・早退については**区分のみ記録し、実際の入室・退出時刻は記録しない**。教職員が判定して区分を選択する。
- 同じ授業で遅刻と早退に該当する場合は**早退を優先**する。
- 公欠は実施された授業の対象科目に対して1コマ認定する。休校とは区別する。
- 認定出席コマ数は整数の0または1とし、0.5コマなどの部分認定は行わない。
- 朝HRも出欠確認対象とする。ただし進級対象科目の総コマ・認定出席コマには含めない。

### 9.2 機能要件

- **ATT-01**　HR・各授業について、生徒ごと・授業実施枠ごとに出欠を確認・記録する

- **ATT-02**　朝HRはコース別に出欠を扱いつつ、同一クラスでは共通座席表で確認できる

- **ATT-03**　通常は担任が欠席・遅刻・早退・公欠等の事前連絡を登録する。ほかの教職員が連絡を受けた場合は担任へ伝達する運用を基本とするが、**事前情報の登録権限は全教職員に共通**とする

- **ATT-04**　終日欠席等は対象日の授業全体の事前情報として一括登録できる

- **ATT-05**　事前登録後に日別授業が変更された場合、新しい対象授業へ事前情報を反映する

- **ATT-06**　確定出欠がある場合はそれを優先表示し、ない場合は事前情報や前時限等から候補表示する

- **ATT-07**　座席表で出欠を確認し、個々の生徒の出欠区分を編集できる

- **ATT-08**　事前情報や候補を確認後、**通常は当該授業の担当教員が対象生徒全員の出欠を一括して手動で確定・保存**する。**確定操作は担当外の教職員にも許可**し、この時点で授業を実施済みと扱う

- **ATT-09**　授業途中で区分が変わった場合は再確認・手動再保存できる

- **ATT-10**　出欠未登録の生徒を**自動保存・自動確定しない**

- **ATT-11**　全教職員が全授業の過去の出欠を個別登録・訂正できる

- **ATT-12**　訂正前の値の専用履歴は保持せず、対象授業の現行出欠を更新する

- **ATT-13**　生徒は本人の出欠履歴、教職員は全生徒・全授業の出欠履歴を閲覧できる

- **ATT-14**　確定出欠の変更後、関連するコマ数・進級指標を再計算して表示する

- **ATT-15**　授業の対象生徒の一部に未確定出欠がある間は、その授業を「実施済み」扱いせず、授業全体の総コマ数・個人の認定コマ数の集計に算入しない

- **ATT-16**　休学中の生徒に対して新しい出欠・成績・就活記録の登録を受け付けない

**座席表の基本操作**：座席をクリックするごとに **出席 → 欠席 → 遅刻 → 早退 → 公欠 → 出席** の順で区分を巡回させる。画面上の選択と授業の確定保存は別操作であり、選択のみでは認定コマを計上しない。

### 9.3 候補の継承

| 継承元の確定出欠 | 次の授業での初期候補 |
|---|---|
| 出席 | 出席 |
| 欠席 | 欠席 |
| 遅刻 | 出席 |
| 早退 | 欠席 |
| 公欠 | 公欠 |

**初期表示の優先順序**

1. 対象授業の**確定出欠**：存在すれば現行の確定値を表示する。
2. 対象授業の**事前出欠情報**：当該生徒について存在すれば、事前連絡であることを示して候補に利用する。
3. 直近のHR・前時限の**確定出欠**：上記がない場合は対応表で変換し、候補表示する。
4. いずれもなければ**未登録**とし、担当教員に確認を求める。

- 候補表示しただけでは当該授業に確定出欠は生じない。
- 事前情報が実際と異なる場合、教職員が確認して実際の区分に修正する。
- 未来の事前情報は認定出席コマ数へ先取り計上しない。
- 出欠を確定せず画面を離れた場合は未確定のままとする。未登録者の自動保存は行わない。**対象生徒全員が確定していなければ授業全体を実施済み・集計対象にしない。**
- **保存済みの確定出欠は次時限の候補に利用できる**。前時限自体が未確定なら、当該時限を確定情報の継承元にはしない。

### 9.4 修正・例外

- 授業中に遅刻者が来た場合、教職員が当該生徒の出欠を更新して再保存する。
- 早退が判明した場合も再保存し、その授業の認定は0コマとする。
- 過去の出欠忘れや誤りは全教職員が訂正でき、表示する集計結果は訂正後の値に更新する。
- **確定出欠が1件でもある授業そのものの時間割変更は一切禁止**する。時間割変更のために出欠を一時解除する例外も規定しない。これと区別し、**出欠区分の訂正は全教職員が可能**とする。
- 欠席・遅刻・早退・公欠の事前情報は、出欠実績と混同せず、授業担当教員による確認を経て確定する。

## 10. 科目別コマ数・進級判定支援

### 10.1 集計対象・授業実施と特殊日程

進級支援では**総授業コマ数（分母）**と**認定出席コマ数（分子）**を整数単位で扱う。科目の年間総コマ数は固定しない。

| 区分 | 総授業コマ数 | 認定出席コマ数 | 特記事項 |
|---|---:|---:|---|
| 通常授業 | 対象者全員の出欠を教職員が一括確定した時点で対象科目へ1 | 出席・公欠1、他0 | 授業確定前は対象者全員分を集計しない |
| 休校・休日・長期休暇 | 0 | 0 | 休校の予定科目へ振替換算しない |
| 試験・HR | 0 | 0 | HRの出欠自体は管理し、次時限の候補に利用 |
| 学校行事 | 対象時限数を指定算入先科目へ加算 | **一部時限でも参加した生徒に行事全コマ数を認定**。不参加は0 | 学校が途中早退を参加と認めた場合も行事全コマを認定 |
| 公欠 | 通常授業の総コマは1 | 当該生徒に1 | 授業の確定を要する |
| 手動コマ換算 | ― | ― | **初期版では提供しない**（学校行事の換算のみ） |

**授業実施済みの確定**：教職員が当該授業の**すべての出欠対象生徒の出欠を一括して確定**した時点で、その授業を実施済みとする。通常は授業担当教員が行うが、担当外の教職員の確定も有効とする。授業が終了していても、1人でも未確定であれば授業全体のコマを集計しない。確定後の出欠訂正は総コマ数・認定コマ数の表示に反映する。

**学校行事**：学校全体で共有する年間日程として行事を登録し、**対象の各教育課程の時間割に同じ学校行事を割り当てる**。行事の算入先科目と対象時限を教職員が指定し、時限数を総コマへ換算する。行事の参加確認は**全教職員が登録・訂正可能**。行事の一部時限に参加した場合も全対象時限数を認定する。途中早退については**学校が参加を認めた場合に全コマ認定**。同じ科目・時限の重複算入は禁止する。

**在籍・休学**：途中入学・編入は取り扱わない。休学は年度・学期の境界から反映し、休学中は出欠・成績・就活記録を作成しない。休学前の実績は保持し、在籍中の通常集計と休学期間を混同しない。休学中の個人に「欠席」の実績を作成せず、年度全体を集計の基本期間とする（休学による生徒別の進級の最終扱いは教員判断であり、システムが進級を自動確定しない）。

**履修開始前**：学期境界等で履修開始日以前にあたる場合、履修開始前と表示し欠席記録を作成しない。途中入学を許容する意味ではない。

### 10.2 進級基準

科目ごとの年度末の確定総授業コマ数の **3分の2以上** を認定出席していれば、当該科目の出席基準を満たす。

```text
科目別出席基準の達成：3 × 認定出席コマ数 >= 2 × 総授業コマ数
```

- 判定は整数による厳密な比較とし、画面上に表示する丸めた百分率では判定しない。
- すべての出欠・授業が確定した年度末に実績値で判断する。
- 出席基準の達成は進級の**最終決定そのものではない**。最終判断は教員が行う。

### 10.3 年度末の概算予測

**確定した概算方式**：残りの授業コマ数は、**残り授業週数 × 週当たりのテンプレート配置コマ数**だけで概算する。**日別振替・行事・休校による将来分の補正は行わない**。**まだ完了していない週の端数は切り捨てる**。実績に確定してから実績値へ反映する。

| 記号 | 定義 |
|---|---|
| `T` | 科目の実施済み総授業コマ数 |
| `A` | 生徒の累積認定出席コマ数 |
| `Cᵢ` | 残る学期区分 `i` の週当たりの当該科目のテンプレート配置コマ数 |
| `Lᵢ` | 当該科目の開講対象となる残りの**完了していない週の端数を含めない整数週数**（休暇等の授業がない週を除外） |
| `F` | 残り予測授業コマ数（概算） |
| `N` | 年度末総授業コマ数見込み（概算） |
| `B` | 年度末の見込み総コマ数に対する必要認定出席コマ数 |
| `R` | 残り必要認定出席コマ数 |
| `P` | 現在までの出席ペース（百分率） |
| `Q` | 残り必要出席率（百分率） |

| 指標 | 計算式・基準 |
|---|---|
| 現在の出席ペース | `P = A / T × 100`（`T > 0` の場合） |
| 残り予測授業コマ数 | `F = Σ(Cᵢ × Lᵢ)`。学期ごとに時間割が違えば各区分の結果を合算 |
| 年度末総授業コマ数見込み | `N = T + F` |
| 必要認定出席コマ数 | `B = ceil(2 × N / 3)` |
| 残り必要認定出席コマ数 | `R = max(0, B - A)` |
| 残り必要出席率 | `Q = R / F × 100`（`F > 0` の場合） |
| 同ペース継続時の認定コマ数見込み | `A + (P / 100) × F`（参考予測値） |
| 残り欠席可能コマ数の目安 | `max(0, F - R)` |
| 年度末の出席基準判定 | `3A >= 2T`（年度内全授業終了後） |

- `ceil` は整数への切上げとする。実績としての認定コマ数は常に整数。予測表示上の期待値は小数になり得るため、**予測値**と明示する。
- 学期によりテンプレートが異なれば、当該学期の `Cᵢ` と `Lᵢ` を使う。
- `Lᵢ` は**完了していない週の端数を切り捨てる**整数週数とし、小数週を用いない。たとえば対象期間が残り3週と数日なら `Lᵢ = 3` とする。現在進行中の週の残り曜日も概算に含めないので、実際の将来実施数と一致しない可能性を明示する。すでに実績に算入したコマと重複計上しない。
- `T = 0` では `P` を算出せず「算出対象外」と表示する。基準テンプレートがあれば `F` は算出可能。
- `F = 0` では `Q` を算出せず「算出対象外」と表示し、その時点で `3A >= 2T` を確認する。ただし年度内全授業が終わっていなければ確定判定と混同しない。
- 未来の休校・振替・学校行事が予測と異なれば、実施後に実績値を取り込み再計算する。
- 年度末予測は**概算**であり、予測数値に基づいて進級不可を確定しない。

### 10.4 出席ペース・リスク表示

| 分類 | 判定内容 |
|---|---|
| 現在基準ペース以上 | `3A >= 2T`（`T > 0` の場合） |
| 現在基準ペース未満 | `3A < 2T`（`T > 0` の場合） |
| 今後の達成見込みあり | `R <= F`（残り予測分に必要数の出席ができる場合） |
| 予測上の達成困難 | `R > F`（残りを全出席しても見込みでは不足） |
| 見込み必要数の達成済み | `R = 0`（**最終進級確定ではない**） |
| 実績なし | `T = 0`。現在ペースは表示しない |

教職員向けにリスク対象者の一覧・絞り込み、本人・科目別の根拠表示を提供する。生徒には本人の科目別指標を表示する。すべて「現在の実績」「概算予測」「年度末の確定基準」を区別する。

### 10.5 計算例

実施済み60コマ、認定出席36コマ、週5コマ・残り8週とする。

| 項目 | 結果 |
|---|---:|
| 現在の出席ペース | `36 / 60 × 100 = 60%` |
| 残り予測コマ数 `F` | `5 × 8 = 40` |
| 年度末総コマ見込み `N` | `60 + 40 = 100` |
| 必要認定コマ数 `B` | `ceil(200/3) = 67` |
| 残り必要認定コマ数 `R` | `67 - 36 = 31` |
| 残り必要出席率 `Q` | `31 / 40 × 100 = 77.5%` |

現在ペースは基準未満だが、概算の残り40コマ中31コマを認定出席できれば達成見込みとなる。これは**予測上の判断**であり、確定した進級判断ではない。

## 11. 成績管理

### 11.1 業務ルール

- 年度は前期・後期の2学期とする。
- 各科目について、通常は科目担当教員が生徒・学期ごとに**0～100点**の評価点を登録する。登録・編集・確定の操作は担当外の教職員にも許可する。
- 試験ごとの点数や平常点の内訳は管理しない。学期別評価点の決め方は各担当教員の採点運用に委ねる。
- 学期ごとにA～Dは付与せず、**年間平均点に対してA～Dを付与**する。
- 前期・後期の両方で開講する科目の年間平均は `(前期評価点 + 後期評価点) / 2` とする。
- **片学期だけ開講する科目**は、その学期の評価点をそのまま年間平均・年間評価の判定に用いる。
- 年間平均の小数部分を**丸めず**に評価区分の境界値と比較する。
- 未入力と0点を区別する。必要な学期の評価点が不足する科目は年間評価を未確定とする。
- 追試・再試等の採点後に確定するまで評価点を未確定にできる。
- 教職員が評価点を**確定した時点で生徒本人に公開**する。通常は科目担当教員が確定する。
- 公開後も全教職員が評価点を**訂正できる**。**訂正後の点数は教職員が再確定した時点で生徒画面へ反映し、訂正通知は行わない**。通常は科目担当教員が訂正・再確定を担当する。確定済みの評価点のみを対象に年間成績・統計を更新する。

### 11.2 年間評価の基準

| 年間平均点（丸めない） | 評価 |
|---|---|
| `80 <= 平均 <= 100` | A |
| `70 <= 平均 < 80` | B |
| `60 <= 平均 < 70` | C |
| `0 <= 平均 < 60` | D |

たとえば79.5点はB、69.5点はC、59.5点はDとなる。A～Dを使用し、「優・良・可・不可」を評価記号として併記しない。

### 11.3 機能要件

- **GRD-01**　全教職員が学期別・生徒別・科目別の評価点を登録・更新できる。通常は科目担当教員が実施する

- **GRD-02**　評価点の未入力、入力済み未確定、確定を区別する

- **GRD-03**　確定した評価点を生徒へ公開する

- **GRD-04**　全教職員が確定・公開後も評価点を訂正でき、**再確定した時点で**生徒画面へ反映する。通知はしない

- **GRD-05**　対象科目が前後期開講か片学期開講かに応じて年間平均を算出する

- **GRD-06**　年間平均を丸めずA～Dの年間評価へ変換する

- **GRD-07**　生徒は本人の当年度・過年度の学期別評価点、年間平均点、年間評価を閲覧できる

- **GRD-08**　教職員は科目・学期・生徒・点数・評価区分で一覧を検索・絞り込み・並べ替えできる

- **GRD-09**　**同一年度・同一科目のうち確定済み評価点のある生徒**を母集団に、**学期別評価点と年間平均点の双方**について平均点・偏差値・順位（競技順位方式）を算出する

- **GRD-10**　同点者は**同順位**とし、次の順位は人数分飛ばす競技順位（例：1位、1位、3位）とする

- **GRD-11**　年間評価Dの科目は注意表示する

- **GRD-12**　教職員は成績一覧をPDFで出力できる

- **GRD-13**　平均点・偏差値を小数第2位まで表示する（表示時の丸めは統計・成績評価の内部判定値に影響させない）

- **GRD-14**　1人・全員同点の場合も平均と順位を計算する。偏差値が数学的に定義できない場合は「算出不可」と表示する

**統計計算の確定式**（対象母集団の確定点を `x₁,…,xₙ` とする）

- 平均 `μ = Σxᵢ / n`。
- **母集団標準偏差** `σ = sqrt(Σ(xᵢ−μ)² / n)`。
- 偏差値 `50 + 10 × (x−μ) / σ`（`σ > 0` に限る）。
- 年間平均点と学期別評価点の両方を別々に算出し、平均・偏差値は**小数第2位まで表示**する。
- 同点者は1位・1位・3位方式とし、順位は算出可能な人数が1人の場合も1位とする。
- **`n = 1` または全員同点で `σ = 0` のとき**は数学的に偏差値が未定義であるため、平均・順位は表示し、偏差値欄は**「算出不可」**とする。
- 未確定点は集計母集団に含めない。未確定と0点を区別する。表示用の丸めは年間評価A〜Dの区分判定に影響させない。
- 生徒には個人を識別できる他人の成績を見せず、平均等の集計値だけを表示する。

## 12. 資格取得管理

### 12.1 業務要件・業務ルール

- **教職員全員（外部講師を含む）**が資格の受験・取得情報を登録・訂正できる。生徒は本人情報の閲覧のみできる。
- 教職員が資格名称一覧を登録・管理し、資格の登録時はその一覧から選択する。資格の**有効期限の有無を教職員が確認・確定**してから記録する。「不明な期限」を確定資格として登録しない。
- 受験**予定は対象外**。受験後には結果待ち・不合格・合格を区別し、同じ資格の再受験・更新・再取得については**過去の記録を残して新たな記録を追加**する。
- 記録する日付は**受験日と取得日**。結果待ちは受験者からの報告で登録できるが、**合格・取得の確定には合格証・認定証等の現物確認が必要**。証明書が確認できない合格報告は結果待ち・未確認として扱う。
- 合格証・認定証のファイルは**システムに保存しない**。教職員が現物等を確認して結果を更新する。
- 有効期限なしの資格は**「無期限（有効）」**と表示する。有効期限を設定した資格は**期限当日まで有効、翌日から失効**する。新しい資格記録によって古い受験履歴を削除しない。

### 12.2 機能要件

- **QLF-01**　教職員が資格・試験名称の共通一覧を登録・編集し、一覧から対象資格を選択する

- **QLF-02**　生徒・資格・受験回ごとに受験日、取得日（取得時）、結果、必要に応じ有効期限を管理する

- **QLF-03**　結果待ち・不合格・合格を区別し、未確認の合格報告は結果待ちにする

- **QLF-04**　取得・合格の確定前に教職員が証明書等の原本・現物を確認する。ファイルは保存しない

- **QLF-05**　再受験・更新・再取得時は新しい履歴を追加し、以前の履歴を残す

- **QLF-06**　期限なしは「無期限（有効）」、期限ありは期限当日まで有効・翌日から失効と表示する

- **QLF-07**　期限の有無や期限日を教職員が確認・確定するまで取得資格を確定しない

- **QLF-08**　登録・訂正は全教職員（外部講師を含む）ができる。教職員は全生徒分を閲覧でき、生徒は本人分のみ閲覧できる

- **QLF-09**　受験前の予定管理、資格証明書のファイル保存、生徒からの結果直接登録は提供しない

## 13. 就職活動管理

### 13.1 企業・応募・選考の管理

- **JOB-01**　企業名等の企業情報を登録・編集・参照する

- **JOB-02**　企業が実際に持つ事業所・勤務地を管理する。生徒の希望勤務地は管理しない

- **JOB-03**　生徒が複数企業への応募を並行して登録・更新できる

- **JOB-04**　同一企業への再応募は別件の応募として登録し、元の応募記録を保持する

- **JOB-05**　企業別メモ、検討・応募の経過、各選考を管理する

- **JOB-06**　企業への応募ごとに全選考段階を進捗ステップで表示する

- **JOB-07**　選考日程未定・結果未判明を許容する

- **JOB-08**　選考種別、予定／実施状態、個別結果、応募全体の状態を区別する

- **JOB-09**　日付未定の選考を含め、**生徒が手動で指定する選考順序**で表示する

- **JOB-10**　生徒・企業・選考種別・個別結果・全体状態で検索・絞り込みできる

- **JOB-11**　教職員は全生徒の応募・選考の進捗を参照し、支援する

### 13.2 選考種別・状態と状態遷移

| 概念 | 確定した選択値・規則 |
|---|---|
| 選考種別 | 受験検討、会社説明会、書類選考、WEBテスト、筆記試験、1〜4次面接、最終面接、その他（生徒が具体名を入力）など、選考・活動の内容 |
| 選考の実施状態 | **予定／実施済み**。延期は予定日を変更し、独立した「延期」は設けない |
| 個別結果 | **未判明／通過／不通過／選考対象外** |
| 応募全体の基本状態 | **検討中／応募済み／選考中／内々定／内定／不合格／辞退** |
| 応募全体の例外状態 | **中止**（辞退以外の理由で応募先による選考が中止された場合に限定） |

**確定業務ルール**

1. **応募全体の状態は、選考結果・応募や辞退などの当該応募の業務操作を根拠にシステムが自動で更新する**。生徒は応募全体の状態を直接入力・編集できない。
2. 個別結果と応募全体の状態が矛盾する更新は保存せず、理由を示す。予定段階で結果を入力したときは**対象選考を自動的に実施済みにする**。
3. **通過／不通過**は各選考段階の結果、**内々定／内定**は応募全体の到達状態として扱う。内々定から内定への遷移を許可し、同一応募による内々定・内定は内定数で二重計上しない。
4. 応募全体が**不合格**になったら同じ応募を再開しない。再び挑戦する場合は**新しい応募**を登録する。
5. 応募全体が**辞退**となったら、その応募の未実施予定選考を削除し、対応する未使用の校内予約を自動取消する。辞退後に同一応募を再開する操作は提供しない。
6. **辞退以外の理由による中止**では未実施の予定選考を削除し、応募全体を**中止**とする。個別の予定選考だけを実施せず取りやめる場合は、その選考のみ削除する。実施済みの選考履歴は残す。
7. 日程が未定でも選考を作成でき、**表示順は生徒が手動指定**する。表示順を決めるためだけに架空の日付を記入しない。
8. 退学・卒業等で本人アカウントが停止しても、過去の応募履歴は学校の保存規程に従う。

**状態間の整合**：状態の更新は対象の確定済み業務操作を反映する。たとえば応募記録の作成時は検討中、実際の応募登録で応募済み、選考の進行で選考中、内々定・正式内定の登録で内々定・内定、選考不通過による応募終了で不合格、本人の辞退操作で辞退、辞退以外の中止で中止を表示する。**個別選考の「通過」だけを「内定」とは見なさない**。最終結果の事実と手動編集可能な応募状態を混同しない。

### 13.3 就職活動の統計・注意表示

- **JOB-12**　エントリー数は**実際に応募した回数**。同一企業への再応募も別件として数える

- **JOB-13**　**内々定も内定に含める**。同一応募の内々定から内定への変更は重複計上しない

- **JOB-14**　**現在の内定数**（未辞退の内々定・内定）と**累計内定数**（後に辞退したものも含む）を両方表示する

- **JOB-15**　生徒・教職員が比較集団を**同一コース／同一学科／同一クラス／同一学年（全学科）**から選べる

- **JOB-16**　比較集団は**対象学校年度の現在在籍している生徒**。卒業・退学者、休学者は除外する。本人は含め、応募0件の生徒も0として含める

- **JOB-17**　比較集団のエントリー数・内定数の平均値・中央値と本人の値を並べて表示する

- **JOB-18**　**本人の値が平均値と中央値の両方を下回る場合に限り**注意表示する

- **JOB-19**　**比較対象が1〜2人の場合は平均値・中央値を表示するが注意表示は出さない**

- **JOB-20**　教職員向けにエントリー数・内定数の並べ替え・絞り込み・支援対象者一覧を提供する

- 同一学年（全学科）は**同じ学校年度の同じ学年の全在籍生徒**を対象とする。
- 当該学校年度・本人所属を基準に比較集団を作る。卒業・退学・休学中の生徒は統計対象に含めない。**応募件数0の在籍生徒を除外しない**。
- 比較は対象集団の数値を示す注意喚起であり、内定・進級等の決定ではない。比較対象者が1〜2人であれば値だけ表示する。

### 13.4 選考会場・校内教室予約

- **RES-01**　会場を自宅・企業・学校等に区分して記録する

- **RES-02**　教職員が校内の**選考用部屋**の一覧を登録・管理する

- **RES-03**　生徒と教職員が空き時間を確認し、予約する。生徒は空き状況のみ、教職員は予約者等の詳細も閲覧できる

- **RES-04**　学校の**平日共通の開校時間を教職員が登録**する。予約は開校時間内に限る

- **RES-05**　開始・終了時刻は**1分単位**で指定する。開始が終了以降になる予約は禁止する

- **RES-06**　同一の選考用部屋について、**予約の前後に各5分以上の空き時間**を必須とする。時間帯の重複・準備時間違反を拒否する

- **RES-07**　**予約開始前なら直前でも**予約・変更・取消可能。開始時刻を過ぎた後は、**生徒・教職員の誰も変更・取消不可**

- **RES-08**　予定選考の日程が変わった場合、生徒または教職員が**既存予約を削除し新しい日時で予約し直す**。自動振替はしない。開始後の予約は削除不可

- **RES-09**　学校が臨時休校・休日になった際は、該当する未開始予約を**自動取消**し、枠を解放する

- **RES-10**　応募辞退時、未実施予定選考に紐づく**未使用予約を自動取消**する。ただし既に開始した予約の取消は行わない

- **RES-11**　取消した予約の専用履歴は保持しない。予約の削除後は再予約可能

**予約可否**：希望時間 `[開始,終了)` に加えて、直前・直後に**それぞれ5分の緩衝時間**が必要である。直前予約の終了から新規予約の開始まで、および新規予約の終了から直後予約の開始まで、それぞれ5分以上の間隔を確保する。重複がない場合でも準備時間が不足すれば登録できない。

**開校時間と休校**：教職員が年間を通じて毎平日に共通する開校時間帯を登録する。休日・臨時休校は年間日程に従って予約不可とし、後から休日・休校になった日については**未開始予約を自動取消**する。予約取消の通知機能は確定要件に含めない（画面に最新の予約状況を表示する）。

**変更・取消の整合**：開始済み予約はいかなる利用者も変更・取消できない。選考日程が変更されても、開始済み予約はそのまま残し、必要な新日時の予約を別途行う。辞退や休校による自動取消は**まだ開始していない予約**だけに適用する。

### 13.5 教職員からの連絡・Gmailとの連携

- **MAIL-01**　教職員が連絡対象の生徒を指定し、個別メールまたは**同一本文のBCC一括メール**を選べる

- **MAIL-02**　選択した宛先・件名・本文をGmail作成画面へ**URL連携**で引き渡す

- **MAIL-03**　利用者がGmail側で宛先・本文を確認・編集し、**Gmail上で送信**する。URLを開いただけで送信済みとはしない

- **MAIL-04**　BCC一括作成では生徒同士に宛先を公開しない。**個別の氏名等の差し込みはしない**

- **MAIL-05**　GmailのURL制約などで一括作成が困難なら、**一括作成を中止して個別メールへ切替**する。BCC件数を固定せず、利用可能範囲で作成し、超過時は利用者が手動分割する

- **MAIL-06**　システム内に送信前の追加確認画面は設けず、**Gmailの作成画面で確認**する（証明書申請の申請内容確認は別要件）

- **MAIL-07**　Gmailが開けない・ログインできない場合はログインを案内し、宛先・件名・本文をコピーできるようにする

- URL連携は**メール作成画面を起動するだけ**であり、Gmail APIによるバックグラウンド送信や自動送信、送信完了の取得を意味しない。
- Gmail作成画面がモーダル・新規タブ・別画面のいずれで開くかはGmailとブラウザの仕様に依存する。モーダルであることは保証しない。
- Gmail作成画面では人が確認して送る。送信しないまま離脱してもシステム側は送信済みと表示しない。

## 14. 帳票・履歴書・証明書申請

### 14.1 出席PDF

**出席PDFは教職員のみ出力可能**。生徒本人・任意期間について次の内容を表示する。

- **RPT-01**　氏名、学籍番号、学科、コース、期間、**出力日（年月日）**を表示

- **RPT-02**　科目別実施済み総コマ数・認定出席コマ数・遅刻・早退・欠席・公欠の実績を表示

- **RPT-03**　出席ペース、年度末概算コマ数、残り予測コマ数、必要コマ数、残り必要出席率、リスクと根拠を表示

- **RPT-04**　**全教職員**が家庭向けの任意の学校連絡事項を入力・付記できる。通常は担任が担当する

- **RPT-05**　学校名を表示する。ロゴ・住所・電話番号の併記は必須としない

- **RPT-06**　実績・未確定情報・概算予測を区別し、PDF上の出力日（年月日）を示す

### 14.2 成績PDF

- **RPT-07**　**教職員のみ**が成績PDFを出力できる

- **RPT-08**　**年度一覧形式と学期一覧形式を選択**できる。氏名、学籍番号、学科・コース、年度・学期、科目、評価点、年間平均、A〜Dを必要な範囲で表示

- **RPT-09**　未確定の成績を含んでも出力可能。未確定を明示し、0点と混同しない

- **RPT-10**　過年度の確定記録も許可範囲で出力できる。学校名・出力日を表示する

### 14.3 履歴書PDF

- **DOC-01**　**厚生労働省の履歴書様式を参考**にした一般的な**A4・1ページ**の日本語PDFを作成する

- **DOC-02**　学校に登録済みの氏名・住所等の基本情報は自動入力し、未登録・不足項目を生徒が補える

- **DOC-03**　生徒は証明写真の画像をアップロードし、PDFの写真位置に挿入できる

- **DOC-04**　生徒は自己PR・志望動機などの自由記述を入力し、**保存・再編集・再保存・再出力**できる

- **DOC-05**　**生徒本人と全教職員**が履歴書PDFを出力できる（生徒は本人分のみ）

- **DOC-06**　学校名は帳票の必要箇所に表示する。Excel形式の出力は初期版に含めない

**レイアウト制約**：1ページ指定と参考様式のすべての項目が両立しない場合でも、項目を利用者への説明なく自動的に削除したり極端に縮小したりしない。A4・1ページの設計範囲で入力内容が収まるように記入欄や文字量を制御し、はみ出す場合は出力前に修正を求める。

### 14.4 成績証明書・卒業見込み証明書の申請

- **DOC-07**　生徒が**証明書種類・提出先企業・必要部数・希望日・用途・学年・学科・コース・氏名**を申請内容として入力する

- **DOC-08**　学校指定の証明書担当教員をメールの宛先に設定する

- **DOC-09**　メールを生成する前に**申請内容の確認画面**を1回表示し、誤申請を防ぐ

- **DOC-10**　Gmailのメール作成画面へ申請内容を渡し、**生徒本人がGmail上で送信**する

- **DOC-11**　システムはメール本文のみを生成し、**申請履歴・送信済み・受理状態を保存しない**

- **DOC-12**　送信後の訂正・再申請・取消は証明書担当教員へ**直接連絡**して対応する

- **DOC-13**　申請受付時には生徒へ**担当教員からメールで受付連絡**する。自動受付メールは作成しない

- **DOC-14**　証明書そのものの自動発行・発行進捗管理は対象外とする

**送信完了の意味**：システム側で申請確認画面を通過しただけでは送信完了にも申請受付にもならない。Gmailで生徒本人が送信し、受け取った学校の証明書担当教員が確認して受付メールを送る運用とする。送信や受付をシステムが自動検知する機能は設けない。

## 15. 非機能要件・運用方針

### 15.1 技術・画面の前提

| 区分 | 方針 |
|---|---|
| サーバー | **JDK 25**、Java、JSP、Servlet、JDBC、Apache Tomcat |
| フロントエンド | HTML、Tailwind CSS、daisyUI、JavaScript、HTMX |
| データ管理 | MySQL |
| 画面構成 | JSP／ServletによるMPAを基本とし、HTMXでHTML断片を更新するHDA |
| デザイン | PC・スマホ対応、ライト／ダークモード |

### 15.2 非機能要件

- **NFR-01｜対応端末**
  教職員・生徒ともPC・スマートフォン

- **NFR-02｜ブラウザ**
  **Chrome、Edge、Safari、Firefoxの現行版**

- **NFR-03｜対応OS**
  **Windows 11、macOS、iOS、Androidの現行サポート版**

- **NFR-04｜応答**
  **すべての通常画面操作の95%以上が3秒以内**。PDF出力・大規模な一括処理は除外し正常完了を確認

- **NFR-05｜同時利用**
  同時利用100人程度は参考規模とし、**100人同時操作の性能保証・専用負荷試験は要求しない**

- **NFR-06｜稼働**
  開校時間外・休日も原則利用可能。ただし**稼働保証は学校開校時間内のみ**

- **NFR-07｜障害復旧**
  **復旧目標4時間以内**。障害中は紙の出席簿で出欠を記録し、復旧後に転記する

- **NFR-08｜データ保全**
  **確定済みデータの消失を許容しないことを目標**とする。バックアップの固定頻度は利用者要件として定めない

- **NFR-09｜保管・削除**
  卒業・退学後の個人記録は学校の文書保存規程に従い、**教職員が手動削除**する。削除期限の具体的年数は規程に従う

- **NFR-10｜セッション**
  無操作20分で失効し、再ログインを要求する

- **NFR-11｜ログイン保護**
  **5回連続の認証失敗で15分間制限**し、存在しないIDか誤ったパスワードかを通知しない

- **NFR-12｜資格情報**
  パスワードを安全にハッシュ化等で扱い、平文保存・ログ出力を行わない。担任による再設定でも秘密情報を表示・記録しない

- **NFR-13｜初期パスワード**
  ランダム生成した初期パスワードを本人確認後、**紙の個別通知で配付**する。初回変更は任意

- **NFR-14｜認可・通信**
  HTTPS等で個人情報・認証情報を保護し、全画面・送信処理で権限検査する

- **NFR-15｜Web保護**
  CSRF・XSS・入力改ざん・SQLインジェクション・セッション固定等に対する安全策を講じる

- **NFR-16｜情報公開**
  生徒は他人の個人記録を閲覧・操作できない。予約状況は生徒に空き情報だけを見せる

- **NFR-17｜操作整合性**
  禁止重複・競合する変更・不正な状態遷移を保存時に拒否する

- **NFR-18｜運用ログ**
  学校の既存の技術ログ運用に従い、**独自の監査ログ管理機能は設けない**

- **NFR-19｜障害時転記**
  **全教職員**が紙の出席簿を手分けして転記できる。既存確定出欠との重複・上書き時は警告・確認を必須とする

- **NFR-20｜転記照合**
  **転記した教職員自身**が紙の記録と入力内容を照合する

- **NFR-21｜学籍・アカウント**
  卒業・退学の効力発生日に本人のアカウント停止。退職者は教職員が退職処理を登録した時点で停止

- **NFR-22｜権限切替**
  担当クラス・科目変更の**効力発生日から**ダッシュボードや時間割の担当表示へ反映する。教職員の共通操作権限は変えない

- **NFR-23｜帳票品質**
  PDFの文字化け、欠落、権限外出力を防ぐ。学校名と出力日を表示する

- **NFR-24｜技術**
  開発・稼働時のJavaバージョンは**JDK 25**

**運用上の制約**

- 確定済みデータの消失ゼロは**データ保全の目標**であり、無条件の消失ゼロ保証を意味しない。復旧手段と検証方法はこの目標に基づいて定める。バックアップの固定頻度は指定しない。
- 通常画面操作の95%以上を3秒以内とする応答目標は維持する。ただし同時100人操作を条件とする保証・受入試験は求めない。
- 学校開校時間は、会場予約の可否とシステムの稼働保証を区別する。会場予約は**平日共通の開校時間と学校の日程**に従い、システムは保証時間外でも原則閲覧・操作できる。
- 教職員がログインを再設定する際に本人指定のパスワードを取り扱うため、本人確認・秘匿入力・画面非表示等を設ける。**本人の秘密を教職員が知り得る運用上のリスク**は残るが、本人指定方式を勝手に仮パスワード方式へ置き換えない。
- 技術ログは既存の校内方針で管理し、本システム独自の監査ログUI・操作履歴の登録を追加しない。

## 16. 受入基準

各受入ケースは対応要件の代表的な確認例である。未列挙の要件についても各要件IDと業務ルールを満たすことを受入条件とする。

### 16.1 認証・権限

- **AT-001**　`AUTH-01〜13、NFR-10〜16`
  - **確認内容**：初期パスワードでのログイン、5回失敗後の15分制限、無操作20分失効
  - **期待結果**：認証・制限・再ログインが定義どおり動作し、認証失敗理由を識別できない

- **AT-002**　`AUTH-10、NFR-12`
  - **確認内容**：担当区分にかかわらず教職員が本人確認後、本人指定パスワードへ再設定する
  - **期待結果**：権限外操作を拒否し、秘密情報をログや画面に露出しない

- **AT-003**　`AUTH-11、ADM-06`
  - **確認内容**：生徒が他人の成績・出欠・就活のURLへアクセスする
  - **期待結果**：他人の個人情報の閲覧・操作を拒否する

- **AT-004**　`ADM-07、NFR-21〜22`
  - **確認内容**：卒業・退学、教職員退職処理、担当変更の効力日を迎える
  - **期待結果**：利用停止と担当情報の表示切替が定義どおりに反映される。担当変更のみでは教職員の操作権限は変化しない

- **AT-051**　`3.1〜3.2、ATT-03・08・11、GRD-01・04、QLF-08、RPT-04、AUTH-10`
