# 要件定義書 **multi-management-system**<仮称>

## 目的

宮崎マルチメディア専門学校における生徒情報の管理業務を効率化し、教育および学生支援の質を向上させるため、統合型の「生徒情報管理システム」を開発する。

### 背景と課題

現状、教職員が手作業や分散した個別システム（Excel等）で管理している以下の情報は、業務の属人化や情報の分散を招いている。

- 出欠状況・出席時数
- 履修登録
- 学期別評価点・年間成績
- 就職活動・選考履歴
- 取得資格
- 学科・コース・クラス・時間割・年間日程などの教育運営情報

### 達成目標

1. **情報の一元管理**：教職員が必要な生徒情報を一か所で登録・更新・参照できるようにする。
2. **教員の入力負担軽減**：基本時間割の自動適用、出欠候補の自動継承、座席表からの差分入力によって操作を減らす。
3. **正確性の向上**：時限・科目・年度を区別し、履修や教員・教室の重複を検査する。
4. **学生の利便性向上**：生徒が自身の時間割・出欠・成績・資格・就職活動状況を確認できるようにする。
5. **進級支援**：出席ペースから指標を計算し、教員の注意喚起・判断を支援する。

### 技術・画面仕様

| 項目 | 方針 |
|---|---|
| 開発技術 | HTML、Tailwind CSS（DaisyUI）、JavaScript、Java[JSK25]（JSP、 Servlet）、HTMX、MySQL（JDBC）、Apache Tomcat |
| 開発ツール | VScode、Maven、Git/GitHub、draw.io(フロー図、ER図等作成)、Figma（画面デザイン作成）、chatGPT、Gemini
| 画面構成 | Hypermedia-Driven Application (HDA) ：HTMLをベースにSPA的なUXを実現（HTMXを利用）|
#### 技術選定理由
本システムでは、JSP/Servletによる堅牢なMPA（Multi Page Application）の構造をベースにしつつ、SPA（Single Page Application）のようなシームレスな操作性を実現するため、HTMXを用いたHypermedia-Driven Application（HDA / ハイブリッドMPA/SPA）のアーキテクチャを採用した。一般的にSPA開発では、REST APIサーバー（Spring BootやLaravel等）とフロントエンドフレームワーク（ReactやVue等）の組み合わせがデファクトスタンダードとされる。しかし今回はチーム開発であり、限られた開発期間の中で「メンバーの学習負荷を低く抑えること」と「システムの品質を担保すること」の両立が重要であった。そこで、JSON APIの構築や複雑なフロントエンドのビルド環境を導入するのではなく、サーバー側（Servlet/JSP）から直接HTMLの断片（Fragment）を返却し、ページの一部を動的に書き換える「HTMX」に着目した。HTMLベースで直感的に実装できるため学習コストが非常に低く、MPAのシンプルな構成を維持したままSPAのような快適なUXを実現できる点から、本プロジェクトに最適な技術選定となった。

## 機能・業務要件

### 利用者・権限管理

#### 登場人物と役割

| 利用者 | 主な役割 |
|---|---|
| 生徒 | 自身の履修科目・時間割・出欠・成績・資格・就職活動情報の閲覧、就職活動情報の登録・更新 |
| 担任（HR担当） | クラス・生徒情報の確認、朝HRの出欠登録、事前の出欠入力、必要に応じた連絡業務 |
| 教科担当教員 | 担当授業の出席確認・保存、担当科目の学期別評価点の登録・編集 |
| 学校管理者（任意） | 学科・コース・教育課程・クラス・年度・学期・科目・時間割・年間日程等の管理 |
- 時間割の登録・変更は全教職員が行える。
- 生徒は原則として自身の個人情報・記録のみを閲覧する。

### ログイン機能

生徒および教職員がシステムに安全にアクセスし、それぞれの権限に応じた画面へ遷移できる機能を提供する。

#### 認証情報（ID／パスワード）仕様

- **ログインID**：学校配布のメールアドレス
  - 生徒：例 `mmc11111@student.multi-m.ac.jp`
  - 教職員：例 `mmc11111@teacher.multi-m.ac.jp`
- **初期パスワード**：システム管理側がランダムに発行する一次パスワード
  - **パスワード変更時の規則**：12文字以上で、英大文字・英小文字・数字・記号の4種類を必須とする
  - **アカウントの対応**：生徒・教職員はそれぞれ必ず1アカウントのみを持ち、1アカウントは生徒か教職員のいずれか一方に対応する

#### ログイン処理・遷移フロー

##### ログイン画面

- メールアドレスとパスワードの入力フォームを表示する。
- 「ログイン」ボタンと「パスワードを忘れた方はこちら」のリンクを設ける。

##### 認証成功時

- 生徒は生徒用ダッシュボードへ遷移する。
- 教職員は教職員用ダッシュボードへ遷移する。
- 生徒が教職員専用URLへアクセスするなど、権限外のアクセスはエラーページを表示して拒否する。
- 生徒は権限のない他者の個人情報を閲覧・変更できないようにする。

##### 認証失敗時

- ログイン画面へ戻し、共通のエラーメッセージを表示する。
  - メールアドレスの存在有無とパスワード誤りを区別して通知しない。（セキュリティ対策）

#### セッション管理

- 無操作状態が20分間続いた場合はセッションを失効させ、再ログインを必要とする。

#### パスワード変更・再設定

- ログイン済みユーザーは、ログイン後画面のパスワード変更画面に遷移し、現在のパスワード・新しいパスワード・新しいパスワード（確認用）を入力して変更する。
  - 現在のパスワードと入力規則を検証する。
- ログイン画面の「パスワードを忘れた方はこちら」では、担任に連絡し、教員の管理画面から再設定してもらう旨をモーダルで案内する。

### 学籍・教育課程・クラス管理

教育課程（年度・学期・学科・コース）・クラス・生徒の所属関係を管理し、年度更新・クラス変更後も過去の所属情報を確認できるようにする。また、教育課程の途中変更、退学、休学などにも対応できるようにする。

#### 基本情報の管理

| 機能 | 概要 |
|---|---|
| 学科管理 | 学科の登録・編集・一覧表示 |
| コース管理 | 学科に所属するコースの登録・編集 |
| 年度管理 | 年度ごとの教育課程・時間割・学期・年間日程を区別 |
| 学期管理 | 1年度を学期を管理 |
| 教育課程管理 | 特定の年度・学期・学科・コース・学年を1つの教育課程として登録・管理 |
| クラス管理 | 教育課程に対応するクラスを登録・管理 |
| クラス所属履歴 | 生徒の年度ごとのクラスの所属変更履歴を保持 |
| 担任割当 | クラスに対する担任の割当と履歴を保持 |
| 生徒・教職員情報 | 各利用者の基本情報を管理 |

#### 管理上の規則

- 教育課程は**年度・学期・学科・コース・学年の組合せに対応する教育内容**を表す。
- 科目の配置は、年度の異なる教育課程間で独立させる
- 生徒のクラス所属は上書きせず、クラス所属履歴に保持する。
- 同じ時点で、生徒が所属する現在のクラスは1つとする。
- 1クラスには当該時点で担任が1人いるものとし、担任交代の履歴を保存する。
- 教科担当のみの教職員が存在してもよい。（外部講師など）

### 履修科目管理

必修科目と選択科目を、生徒・教育課程ごとに管理する。選択科目を生徒単位で登録できるようにする。

#### 機能要件

| 機能 | 概要 |
|---|---|
| 科目マスタ管理 | 科目名などを管理 |
| 教育課程別科目管理 | 教育課程ごとに独立して科目を配置 |
| 必修科目の履修 | 対象教育課程の必修科目を生徒の履修対象として設定 |
| 選択科目の履修 | 対象の生徒に対して選択科目を登録・変更 |
| 履修一覧 | 教員・生徒が対象生徒の履修科目を確認 |
| 時間割との連動 | 各生徒の履修科目に対応する授業だけを各生徒の時間割画面に表示、教職員には全コースの時間割および、自身が担当の授業の時間割を表示できる |

### 時間割管理

#### 履修科目・基本情報の管理

学科・コース・学年および生徒の履修登録に応じて、時間割を作成・表示する。時間割の設定と変更は教職員画面で行う。

| 機能 | 概要 |
|---|---|
| 年間日程の登録 | 学校全体の授業日・休日・休校・試験・学校行事・長期休暇などを一括登録・編集、個別登録・編集も可能 |
| 教室管理 | 時間割に割り当てる教室を登録・編集 |
| 科目・担当教員の設定 | 週時間割配置に科目、担当教員（1人）、教室を設定 |
| 履修科目の反映 | 生徒の履修登録を参照し、生徒ごとの時間割を生徒画面に表示 |
| 教員用時間割 | 教員本人の担当授業を日付・時限順に表示し、対象授業の出席管理へ遷移 |
| 生徒用時間割 | 生徒本人の対象授業のみを表示 |
| 表示切替 | 日・週・月単位のカレンダー表示に対応。月単位の場合は、年間日程を表示し、個別の時間割は出さない。 |

#### 週時間割テンプレート・週時間割配置

時間割は**週時間割テンプレートを通常日の基準**として使用し、変更が必要な日・時限だけ個別に編集する。テンプレートのとおりに授業を行う場合、日ごとの登録操作は不要とする。

| 機能 | 概要 |
|---|---|
| 週時間割テンプレート | 教育課程ごとに通常の曜日・時限構成を登録・管理 |
| 週時間割配置 | テンプレート内の曜日・時限・教育課程別科目・担当教員・教室を配置 |
| 複数テンプレート | 学期によって基本時間割が変わるので、同一教育課程に複数のテンプレートを設定可能 |
| 自動反映 | 特にテンプレートの時間割と変更がない場合は対象日の曜日・時限からテンプレートを参照 |
| 選択科目 | 教員画面では選択科目の時限を確認できる。生徒は選択した生徒のみ画面の時間割に表示される |

- 同じ時限に異なる選択科目の配置が並行して存在することは、履修者・教員・教室の重複がなければ許容する。
- テンプレート登録時に、履修者、教員、教室の重複がないかチェックして登録できるようにする

#### 日別時間割変更

特定の日付・時限だけ、週時間割テンプレートから導かれる授業を変更する。基本テンプレートそのものは変更しない。

| 機能 | 概要 |
|---|---|
| 特定日の科目振替 | 当該日時の授業を、別の教育課程別科目に変更 |
| 空き時限への追加 | 授業のない時限に授業を追加する場合にも対応 |
| 教室の扱い | 教室だけの変更は行わず、当該授業の設定上の教室を用いる |

- **特定の時間だけ、その科目の担当教員変更・教室変更・履修者変更は行わない。**
- 担当教員が授業を実施できない場合は、その教員を変更するのではなく、別の科目の授業に振り替える。
- 振替先の教育課程別科目から担当教員および教室、履修者を特定する。


#### 年間日程・特殊日程

年間日程は**原則として学校全体で共通**とする。学科・コース・学年などで個別に異なる授業がある場合は、対象の「日別時間割変更」で手動調整する。

| 日程区分 | 授業コマの扱い |
|---|---|
| 通常授業日 | 対象日に配置された実授業のコマ数を科目別に算入 |
| 休校 | 本来予定されていた科目のコマ数として算入せず、休日扱いになる |
| 公欠 | 公欠生徒に本来予定されていた科目のコマ数として算入（出席扱い） |
| 試験 | 授業コマ数に含めない |
| 学校行事 | 特定科目のコマ数として算入 |
| 休日・長期休暇 | 原則として通常授業を設定しない |

- 学校行事などは特定科目に算入されるが、その特定授業を管理画面（教職員）で選択できるような機能を有する
- 年間日程は期間指定・一括登録を可能にする。
- 年間日程は登録すると、日別時間割変更でその予定が何時限～何時限かを「予定を再登録せず」に時間だけ登録できるようにする。時限に入るわけではない予定の場合は、特に指定しなくてもよいものとする。日別、週別、月別カレンダーには年間日程で登録した予定が表示されており、その予定を時間割に組み込むときに予定をもう一度入力せずに時間帯だけ決められるようなUXにする

#### 授業実施枠

**授業実施枠**は、特定の日付・時限における授業（またはHR等の出席確認対象）を識別する。

- 通常授業は週時間割配置を基に決定し、日別時間割変更がある場合は変更内容を反映する。
- 出席記録は授業実施枠に対応付ける。

#### 授業コマ数の管理・達成予測

科目ごとの授業コマ数で管理する。科目別の総授業コマ数は年度当初に固定せず、時間割・年間日程・日別変更によって変動する。

| 指標 | 算出内容 |
|---|---|
| 実施済み総授業コマ数 | 各科目ごとの現時点での実施済み授業コマ数 |
| 年度末総授業コマ数見込み | 実施済みコマ数に、週時間割テンプレートの科目別配置数と残り授業週数から予測したコマ数を加算 |



#### 時間割管理業務フロー

### 出席管理
#### 機能要件

生徒・授業実施枠ごとに出欠を記録し、座席表からの確認、前時限の情報継承、差分入力によって教員の負担を軽減する。

| 機能 | 概要 |
|---|---|
| 出席情報の自動継承 | 朝HRまたは直近の前時限のDB保存済み出欠を参照し、フロントエンドで当該時限の候補を生成 |
| 座席表による出席確認 | 対象クラス・教室の座席表を表示し、生徒ごとの出欠を確認・変更 |
| 授業実施枠単位の管理 | 授業・HRごとに、生徒の出欠記録を独立して保持 |
| 事前入力 | 担任が未来の対象授業実施枠に対して出欠（候補）を直接登録、実際の出欠確認の時に確定する |
| 保存・自動保存 | 教員が確定した出欠を保存し、候補だったものが確定する |
| 出席記録の閲覧 | 教職員・生徒が権限に応じて履歴を閲覧 |
| 進級判定の支援 | 科目別実施済み授業の出席コマ数と年度末の総授業コマ数見込みから、出席ペースと残り必要出席率を算出・表示 |
| 連絡業務 | 家庭向けの出席情報PDFを出力 |
| 個別修正 | 出欠忘れや、修正のために個別でさかのぼって登録しなおすこともできる |

- 朝HRは授業実施枠として管理する。同一クラス内の各コースに独立したHRの授業実施枠を設け、共通のクラス座席表から確認した結果を該当枠へ保存する。このときの出欠情報が継承され、次の時間の初期出欠候補になる
- 授業実施枠は教育課程（コース）ごとに独立させ、重複がないように登録させる。もし、一致する場合は警告を出して登録できないようにする
#### 出欠区分

出欠は授業実施枠単位で記録し、科目別の**認定出席コマ数は原則として1コマまたは0コマ**で判定する。

| 出欠区分 | 定義・扱い | 認定出席コマ数 |
|---|---|---|
| 出席 | 開始から20分未満に参加し、途中退室せず受講 | 1コマ |
| 遅刻 | 開始から20分以上経過して参加 | **0コマ** |
| 欠席 | 当該授業を受講しなかった | **0コマ** |
| 早退 | 授業途中で退室・下校 | **0コマ** |
| 公欠 | 学校が認める事由で授業を受講できなかったが、出席と同等に扱う | **1コマ** |

- 公欠は休校と異なり、授業自体は出席として扱い、その授業の**算入先科目**に認定出席1コマを計上する。
- HRはシステム上科目として扱い、出席登録もほかの授業と同様に行う。

#### 出席情報の継承

直近の朝HRまたは前時限のDB保存済み出欠を参照し、当該時限の初期候補を生成し、当該時限の座席表に表示する。教員は候補との差分を修正して保存する。

| 前時限の保存済み出欠区分 | 次時限の初期表示 |
|---|---|
| 出席 | 出席候補 |
| 欠席 | 欠席候補 |
| 遅刻 | 出席候補 |
| 早退 | 欠席候補 |
| 公欠 | 公欠候補 |

- 候補はDBに保存しない。画面で候補を表示・変更しただけでは出欠記録は更新しない。
- 事前入力で出欠が登録されている場合は、その保存済み情報を優先する。
- 継承元が存在しない場合は未登録として継承されており、教員が確認して入力する。

#### 出席情報の事前登録・保存・訂正

1. **事前登録**：担任が未来の対象授業実施枠に欠席・遅刻・早退・公欠などを先行登録する。
2. **朝HR**：担任がクラスの座席表で確認し、各コースのHRに出欠を保存する。HRの保存がない場合、次時限の担当教員が出欠を確認する。
3. **授業開始時**：対象授業実施枠の保存済み記録を候補として表示し、未登録者には前時限等から候補を生成する。仮に事前登録者が登録情報と違う出席状態になっても、ここで保存し直せばいい。
4. **授業中**：途中入室・早退などに応じて教員が区分を変更する。
5. **保存**：教員が確認した内容を、当該授業実施枠の出欠記録として保存する。
6. **訂正**：出欠を修正する場合は同じ記録を更新し、訂正履歴は保持しない。
7. **次時限への反映**：保存済み記録は、次時限の出欠候補の生成に利用する。

- 終日欠席などの事前登録は、その日の対象授業実施枠へ一括登録する。
- 事前登録後に時間割が変更された場合、その時間に新たに登録された科目上の出欠に変更する
- 未来の授業への事前登録は、実施済みの認定出席コマ数に先取り計上しない。

### 座席表・座席割当管理

出席登録のため、クラス・教室に対応する座席表と生徒の座席割当を管理する。1つのクラスに複数コースの生徒が所属する場合も、同じ教室で授業を受ける生徒を共通の座席表に表示できるようにする。

#### 座席表・座席の管理

| エンティティ | 役割 |
|---|---|
| 座席表 | クラスと教室に対応する座席レイアウト |
| 座席 | 座席表に属する個々の席と行・列の位置 |
| 座席割当履歴 | 生徒と座席の対応関係および有効期間 |

- 座席の位置は行番号・列番号による単純なグリッドで表現する。
  - 単純な長方形ではない場合、席がない部分には誰も座っていないという表現をする
- 設定画面で行数・列数を入力し、座席を自動生成し、生徒を登録していく
- 実際の通路・机の間隔・不規則な配置は、座席データには保持しない。
- 生徒が割り当てられていない座席は空席として表示する。
- コースごとの移動教室の際には、別々の教室で座席表が表示されるように、クラスとして座席表を持つのではなく、教育課程別科目ごとに座席表を持ち、合同授業の際には、別々のコースで同じ教室の座席を各人登録しても矛盾が生じない座席位置を登録する。
  - 教育課程別の科目ごとに座席表を登録するのは大変なので、クラスで授業を受ける際の座席表、選択授業やコース別授業の時にはそれぞれこの座席表、のような登録の方法にしてやりやすくしたい

#### 席替えと履歴

- 座席を移動した場合は、現在の割当履歴を終了し、新しい割当履歴を作成する。
- 履歴には有効開始日時・有効終了日時を保持する。
- 同一時点で1つの座席に複数生徒を割り当てない。
- 同一時点で1人の生徒に同じクラス内の複数座席を割り当てない。
- 過去の座席配置は、割当の有効期間から再現できるようにする。

### 科目別出席コマ数・進級判定支援

科目別の**総授業コマ数**と生徒の**認定出席コマ数**を比較し、進級に関する状況を表示する。年度末に確定した総授業コマ数の**3分の2以上**を認定出席していれば基準を満たす。進級の最終決定を自動確定するのではなく、教員の判断を支援する。

#### 科目別出席コマ数の管理

| 機能 | 概要 |
|---|---|
| 総授業コマ数の取得 | 実施済み授業実施枠の算入コマ数を、算入先科目ごとに集計 |
| 生徒別認定出席コマ数 | 履修登録と出欠記録から生徒・科目別に出席のコマ数を集計 |
| 進級基準 | 年度末の総授業コマ数の3分の2以上を認定出席していること |
| 動的再計算 | 授業・出欠・時間割・年間日程の変更に応じて集計・予測を再計算 |

- 最終判定は整数で `3 × 認定出席コマ数 >= 2 × 総授業コマ数` と比較する。

#### 出席ペース・年度末予測の算出

**現在までの出席ペース**は、当該科目の実施済み総授業コマ数に対する認定出席コマ数の割合で求める。残りの授業コマ数は、対象学期の週時間割テンプレートに登録された科目別の週時間割配置数を週当たりの基準開講コマ数とし、残り授業週数に応じて予測する。年度末に3分の2を満たすための残り必要出席率を算出する。

| 記号 | 意味 |
|---|---|
| `T` | 当該科目の実施済み総授業コマ数 |
| `A` | 生徒の累積認定出席コマ数（出席・公欠） |
| `C` | 対象学期の週時間割テンプレートで、当該科目に対応する週時間割配置の件数（1週間当たりの基準開講コマ数） |
| `L` | 当該科目の開講対象期間における残り授業週数 |
| `F` | 週時間割テンプレートの配置に基づく残り予測授業コマ数 |
| `N` | 年度末の総授業コマ数見込み |
| `R` | 今後必要な認定出席コマ数 |
| `Q` | 残り予測授業コマ数に対する必要出席率 |

| 指標 | 計算式・扱い |
|---|---|
| 現在の出席ペース | `P = A ÷ T × 100`（`T > 0`） |
| 週当たり基準開講コマ数 | `C = 当該科目の週時間割配置件数` |
| 残り予測授業コマ数 | `F = C × L`（複数学期にまたがる場合は学期ごとの `C × L` を合計） |
| 年度末総授業コマ数見込み | `N = T + F` |
| 年度末必要出席コマ数 | `B = ceil(2 × N ÷ 3)` |
| 今後必要な認定出席コマ数 | `R = max(0, B − A)` |
| **残り必要出席率** | **`Q = R ÷ F × 100`**（`F > 0`） |
| 同ペース継続時の認定出席コマ数見込み | `A + P ÷ 100 × F`（表示用の予測値） |
| 残り欠席可能コマ数の目安 | `max(0, F − R)` |
| 年度末の確定判定 | `3 × A >= 2 × T`（年度内の全授業終了後） |

- `C` は実績から計算せず、対象学期の週時間割配置から取得する。`ceil` は必要な出席コマ数を整数へ切り上げる処理を表す。**認定出席コマ数は常に整数**とし、0.5コマなどの部分出席は認めない。
- `L` は当該科目の開講対象期間に残る授業週数を使用し、休日・長期休暇など授業のない週を除外する。学期ごとにテンプレートが異なる場合は、学期別の配置件数と残り週数から算出して合算する。
- `T = 0` の場合は現在の出席ペースを算出しない。週時間割の配置が登録済みであれば、授業実績がまだなくても残り予測コマ数を算出できる。
- 既に確定している日別時間割変更・休校・学校行事などによって将来の開講コマ数が変わる場合は、同じコマを重複計上しないよう、テンプレートによる予測にその差分を反映する。
- `F = 0` の場合は残り必要出席率を計算せず、現在の認定出席コマ数で3分の2を満たしているか判定する。
- 実施前の時点では将来の休校・時間割変更等が未確定のため、`F`・`N`・`R`・`Q` は**予測値**として表示する。実際の授業コマ数・出欠が更新されたら再計算する。

#### 出席ペース・進級リスク判定

出席状況は**現在の出席ペース `P`** と **今後必要な出席率 `Q`** を分けて表示する。

| 判定項目 | 判定基準・表示 |
|---|---|
| 基準ペース以上 | 実施済み授業に対する出席ペース `P >= 66.67%`（厳密には `3A >= 2T`） |
| 基準ペース未満 | 現在の出席ペースが3分の2未満（`3A < 2T`） |
| 残り必要出席率 | `Q` を数値で表示し、今後どの程度の出席が必要か示す |
| 予測上の達成可能 | `R <= F`（残り予測授業を必要数だけ出席できれば達成） |
| 予測上の達成困難 | `R > F`（残り予測授業を全出席しても不足） |
| 既に必要数を達成 | `R = 0`（現在の年度末総コマ数見込みに対して必要数達成済み） |

- 現在の出席ペースが3分の2未満でも、今後必要な出席率 `Q <= 100%` であれば挽回可能と表示する。
- `Q > 100%` の場合は現在の開講ペースに基づく**予測上の達成困難**とし、確定した進級不可とは表示しない。
- `T = 0` の場合は現在のペース判定を保留する。年度末の確定判定は実績のみで行う。
- 最終的な進級判断は教員が行う。

#### 計算例

ある科目で、実施済み60コマ、認定出席36コマ、週時間割テンプレートに当該科目が週5コマ配置され、残り授業週数8週の場合：

| 指標 | 計算結果 |
|---|---|
| 現在の出席ペース | `36 ÷ 60 = 60%` |
| 週当たり基準開講数 | `週時間割配置5件 = 5コマ` |
| 残り予測授業コマ数 | `5 × 8 = 40コマ` |
| 年度末総授業コマ数見込み | `60 + 40 = 100コマ` |
| 必要な総出席コマ数 | `ceil(100 × 2 ÷ 3) = 67コマ` |
| 残り必要出席コマ数 | `67 − 36 = 31コマ` |
| **残り必要出席率** | **`31 ÷ 40 × 100 = 77.5%`** |

現在は出席ペース60%で基準の3分の2を下回るが、残り40コマのうち31コマ（77.5%）出席できれば、予測総100コマに対する3分の2を達成する。

#### 判定結果の表示

| 機能 | 概要 |
|---|---|
| 生徒別表示 | 生徒の現在の出席ペース、残り必要出席率、予測上の達成可能性を表示 |
| 科目別表示 | 実施済み総授業コマ数、認定出席コマ数、残り予測コマ数、年度末見込みを表示 |
| リスク対象者一覧 | 基準ペース未満、予測上の達成困難などの生徒を抽出 |
| 判定根拠の表示 | 実施済み・出席済みコマ数、授業週数、必要出席コマ数などを提示 |
| 動的更新 | 関連データの変更後、Java側で再計算して表示 |

### 成績評価

各学期の科目別評価点を管理し、**年間平均点に対して「A・B・C・D」の評価を行う**。

#### 成績情報の管理

| 機能 | 概要 |
|---|---|
| 学期別評価点の保持 | 生徒・履修科目・学期ごとに評価点（0～100点）を保存 |
| 年間平均の算出 | 前期・後期の評価点から年間平均を計算 |
| 年間評価の算出 | 年間平均点から優・良・可・不可を判定 |
| 評価点の編集 | 担当教員が評価点を登録・更新 |
| 未入力の扱い | 未入力の学期は0点と区別し、必要な評価点が揃うまで年間評価を未確定として表示 |
| 統計情報 | 同一学科・コース等の対象集団について科目別評価平均点・偏差値・順位を算出・表示 |
| 一覧・絞り込み | 生徒、科目、学期、点数順などで絞り込み |
| 成績PDF出力 | 家庭向けの成績一覧等をPDFとして発行 |

**試験ごとの点数は管理しない。** 試験点数の専用表示も行わない。試験・平常点等をどのように合成して学期評価点を決定するかは、科目ごとの教員の採点運用に委ねる。あくまで最終評価点を記録する。**教員側から全評価項目も保持したいという要請があればこの限りでない。**

#### 学期別評価点と年間評価

年度は前期・後期の2学期とする。両方の学期の評価点が存在する場合、年間平均は次式による。

```text
年間平均点 = (前期評価点 + 後期評価点) / 2
```

| 年間平均点 | 評価記号 |
|---|---|
| 80点以上100点以下 | A |
| 70点以上79点以下 | B |
| 60点以上69点以下 | C |
| 0点以上59点以下 | D |

- **A・B・C・Dは学期ごとの評価点に直接付けず、年間平均に対して判定する。**ただし、学期のみの科目についてはその期間だけの評価点を年間評価点にしてよい。
- 追試・再試等を経て評価点が確定するまで、未入力として管理できる。


#### 成績表示・利用者別の機能

| 利用者 | 画面・機能 |
|---|---|
| 生徒 | 自身の過年度・当年度の学期別科目評価点、年間平均点・年間評価を閲覧 |
| 生徒 | 科目別平均点等を表示。年間評価が不可の場合は注意を表示 |
| 教員 | 担当科目の生徒別・学期別評価点を登録・編集 |
| 教員 | 学期別評価点・年間評価・科目別平均点・偏差値・順位を確認 |
| 教員 | 不可の生徒や評価区分別に絞り込み・色分け表示 |
