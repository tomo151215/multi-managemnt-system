# 生徒情報管理システム 要件定義書

## 1. 目的・対象範囲

学籍・履修・時間割・出欠・成績・資格・就職活動を一元管理し、二重入力と記録の不整合を減らす。教職員の教育・就職支援と、生徒本人による状況確認を支援する。

| 領域 | 提供する機能 |
|---|---|
| 共通 | 認証、アカウント管理、ダッシュボード、検索・絞り込み |
| 教務 | 年度・学期、学科・コース・クラス、学籍・担任、教育課程・履修 |
| 授業・出席 | 年間日程、週時間割・日別変更、教室・座席、事前連絡、出欠、進級判定支援 |
| 成績・資格 | 学期評価点、年間評価、統計、受験・取得・有効期限 |
| 就職支援 | 企業・応募・選考、質問回答、進捗・統計、校内会場予約 |
| 文書・連絡 | 出席・成績・履歴書PDF、Gmail文面作成、証明書申請文面作成 |

## 2. 利用者・認証・共通操作

### 2.1 操作権限

利用者は**生徒／教職員の2区分**。担任・科目担当教員・その他教職員・外部講師の操作権限は同じとし、学校管理者などの追加区分は設けない。担当の割当は初期表示・業務対象の選択に使い、担当外を理由とする操作制限には使わない。

| 操作 | 生徒 | 教職員 |
|---|---|---|
| 教務・出欠・成績・資格の閲覧 | 本人分。成績は公開分 | 全生徒分 |
| 学籍・履修・年間日程・時間割・教室・座席の管理 | 不可 | 可 |
| 事前連絡、出欠の確定・訂正、成績の保存・公開、資格登録 | 不可 | 全生徒・全授業で可 |
| 応募・選考・質問回答の登録・更新 | 本人分 | 閲覧・支援。代理予約に伴う日程・会場調整は可 |
| 校内会場予約 | 本人の選考に対して可 | 生徒の選考の代理予約のみ |
| 履歴書の保存・編集・PDF出力 | 本人分 | 全生徒分 |
| 出席・成績PDF、学校連絡事項の付記、Gmail連絡作成 | 不可 | 可 |
| アカウント発行・停止、本人確認後のパスワード再設定 | 不可 | 可 |
| 証明書申請文面の作成 | 本人分 | 担当者設定・受付連絡 |

生徒は他人の個票を閲覧・更新できない。画面・URL・HTMX通信・PDF出力のすべてに同じ認可を適用する。業務状態による制限は、教職員の担当にかかわらず共通とする。

### 2.2 アカウント・パスワード

| 項目 | 要件 |
|---|---|
| ログイン | 学校配布メールアドレスとパスワードを使用。成功後は利用者別ダッシュボードへ遷移 |
| 対応関係 | 1人1アカウント。生徒・教職員の兼用を禁止 |
| 初期発行 | 教職員がランダムな初期パスワードを発行し、本人確認後に紙で個別配付。初回変更は任意 |
| パスワード変更 | 現行・新規・確認入力で変更。新パスワードは12文字以上、英大文字・英小文字・数字・記号をすべて含む |
| 再設定 | ログイン画面から担任への相談を案内。本人確認後、全教職員が本人指定の新パスワードへ再設定可能。入力は秘匿し、ログ・通知に出力しない |
| 認証失敗 | ID不存在とパスワード誤りを区別しない。失敗回数を保存せず、回数による待機・ロックアウトを設けない |
| セッション | 無操作20分で失効し、再ログインを要求 |
| 生徒の停止 | 卒業・退学の当日に教職員が手動停止。日付到来による自動停止は行わない |
| 教職員の停止 | 退職・契約終了処理を登録した時点で停止 |
| 停止の効果 | 新規ログインと既存セッションからの利用を拒否。停止だけでは過去記録を削除しない |
| 担当交代 | 効力発生日から担当表示を切り替える。教職員の操作権限は変えない |

### 2.3 共通画面・保存

- PC・スマートフォン、ライト・ダークモードに対応する。対象年度・学期・日付・生徒を明示する。
- 日・週の授業表示と、年間日程を中心とする月表示を提供する。月表示には時限ごとの授業詳細を並べない。
- 各領域で検索・絞り込み・並べ替えを提供し、教職員は担当分と全体を切り替えて参照できる。
- 未入力、予定、事前連絡、出欠候補、保存済み実績、公開状態、概算予測を区別する。未入力を0点・欠席・不合格に置き換えない。
- 保存時に必須値・範囲・参照関係・禁止重複・状態遷移を検査し、失敗理由を表示する。同時操作や古い画面からの上書きも検出する。
- 一括確定、予約変更、事前連絡の差し替えなどの複数更新は、全件成功または全件取消とする。二重送信で実績や応募を重複作成しない。

## 3. 学籍・教育課程・履修

### 3.1 年度・所属・異動

- 学校年度は**4月1日〜翌3月31日**、学期は**前期・後期の2期**。学期は年度内に収め、期間を重複させない。
- 学科、学科に属するコース、学年、年度クラス、生徒・教職員の基本情報を管理する。生徒は学籍番号・氏名・ふりがな・生年月日・住所・連絡先・写真・在籍状態などを持つ。
- 生徒の同一学期の所属は1件、同一時点のクラスは1つ。**年度＋コース＋学年が同じ集団を複数クラスへ分割しない**。1クラスに複数コースが所属してよい。
- クラスは運用中、担任1人を持つ。交代の有効期間を管理し、担当不在・期間重複を防ぐ。担任を持たない教職員も許容する。
- 次年度の所属・進級・留年は教職員が手動登録する。転科・転コース・休学・復学等は事前登録し、年度・学期の境界から反映する。旧所属を上書きせず履歴を残す。
- 途中入学・編入、学期途中の休学開始・復学は扱わない。休学期間の新規出欠・成績・就活記録を禁止し、休学前の実績は保持する。
- 写真・住所・連絡先等の未登録を許容する。未登録項目があるだけで学籍の保存を妨げず、帳票等の利用時に必要項目を検証する。

### 3.2 教育課程・科目・履修

- 年度の教育課程にコース・学年・クラス・科目を定め、学期ごとに開講科目を設定する。科目の基本情報と必修／選択の区分を管理する。
- 必修科目は該当する生徒全員を履修対象にする。選択科目は教職員が生徒別・学期別に登録し、**追加・変更・取消は学期開始前に限る**。
- 生徒の時間割・出欠対象・成績対象は本人の履修から決定する。同一生徒が同じ時間帯に複数授業へ参加する配置は認めない。
- 年度・学期・教育課程をまたぐ誤った科目参照や、他人の履修を使った実績登録を禁止する。実績のある履修・所属を別対象へ付け替えたり削除したりしない。
- 年度開始時に前後期の開講・必修履修・選択履修を整備し、片学期科目と後期の設定漏れを区別する。担任・履修・時間割・予測用授業週の設定が不足する場合は「設定未完了」と表示し、年間成績や残り0コマと誤認させない。

## 4. 年間日程・時間割・行事

### 4.1 年間日程の役割

学校共通のカレンダーを使用し、次の情報を分ける。

| 情報 | 管理内容 | 授業・出欠への影響 |
|---|---|---|
| 年間日程の日 | 1日1件の開校状態：開校・休日・休校・長期休暇 | 授業生成・会場予約可否の正本 |
| カレンダー予定 | 日付、名称、行事・試験・連絡等の表示情報。同日に複数登録可能 | 表示のみ。時限・算入先科目・出欠は持たない |
| 時間割の行事 | 1日単位の行事名、対象課程、その日の対象授業・時限 | 実際の授業を行事名で表示し、各授業の科目へ通常どおり算入 |

- 単日編集と期間指定の一括登録を提供する。期間入力は日ごとの登録に展開する。
- **開校状態を確認 → 有効な週時間割を適用 → 配置ごとに日別変更を適用**の順で授業を決める。休日等に授業を行う場合は、先に対象日を開校へ変更する。
- カレンダーに「試験」「交流会」と登録しただけでは、時間割や集計区分を変更しない。両方へ登録する画面を設けても、保存情報は独立させる。
- 休校・休日への変更時は、未実績の授業と未開始予約を整理する。確定出欠のある授業を消す日程変更は拒否する。

### 4.2 週時間割・日別変更

- 学期の教育課程ごとに週時間割テンプレートを1版以上設定する。曜日・時限・開講科目・**担当教員1人**・教室・適用座席表を指定し、空欄時限も許容する。
- 通常日は有効なテンプレートを自動適用する。前後期や将来の変更は適用期間を区切った版として管理する。
- 通常週は月〜金を対象とし、開校とした土日の授業は日別追加で扱う。時間割は本人の履修に絞り、教職員は全コースと自分の担当授業を参照できる。
- 日別変更は、振替・空欄時限への追加・対象授業の取消・試験化・行事表示に対応する。元の週時間割は変更しない。
- 振替・追加・行事の授業内容は、**同じ学期・教育課程の登録済み週時間割配置**から選ぶ。その配置の科目・教員・教室・履修対象者を使用する。
- 並行する選択授業は、日付・時限だけでまとめず**変更元の配置ごとに識別**し、個別に変更できる。
- 当日だけの教員・教室・履修者の差し替えは提供しない。教員不在等は登録済みの別授業への振替で対応する。
- 確定出欠が1件でもある授業は、日時・科目・教員・教室・対象者等を変更できない。週時間割・学期・日程・マスター変更を経由する間接変更も拒否する。出欠区分の訂正は可能とする。

### 4.3 競合・合同授業

生徒・教員・教室の時間帯競合を保存時に拒否する。異なる教育課程で、**同一日・同一科目・同一教員・同一教室・開始終了時刻の完全一致**を満たす場合に限り、教員・教室の重複を合同授業として許可する。

科目名が異なる授業や一部だけの時間重複は合同扱いにしない。合同授業でも授業実施枠・対象者・出欠・集計は課程別に持ち、同一生徒の二重参加や座席重複を認めない。全コースに朝HRを設け、コース別の独立した枠とする。同一クラスでは共通座席表を使用する。

### 4.4 行事の扱い

- 行事は通常授業の表示名を「交流会」「サークル」等に置き換えて表す。科目は各授業に残し、行事専用の参加実績・認定コマ数を別計上しない。
- **出欠・認定は時限ごと**。最初の時限の入力を、同日の同じ行事の対象時限へ一括登録・確定できる。後続時限にだけいる生徒は追加入力を必要とする。
- 一括確定は教職員の明示操作とし、当日の未開始の後続時限にも適用できる。既存出欠がある場合は上書きを確認する。未来日の事前連絡は実績化しない。
- 後から特定時限だけ訂正できる。例：3時限を出席で一括登録後、3限を早退へ訂正すると、**総3コマ・認定2コマ**。1時限の参加で全コマを認定する扱いは行わない。

## 5. 教室・座席・過去状態の保持

- 教室名・用途を管理し、授業用と就活選考用を区別する。
- 座席表はクラス共通を基本とし、コース別・選択授業用も設定できる。行・列による格子、利用しない位置、空席を扱い、実物の寸法・通路幅は扱わない。
- 授業の適用座席表は事前指定し、出欠画面で自動表示する。その場で別の座席表へ切り替えない。**座席表自体が未指定・未登録なら出欠画面を開けず、設定を案内する**。
- 座席表が存在しても未割当の生徒は出欠対象から除外せず、一覧から入力できるようにする。
- 同一時点の同一席への複数割当、同じ授業で1人に複数席を割り当てること、合同授業の座席重複を禁止する。授業の教室と座席表の教室を一致させる。
- 席替えは有効期間付きの割当履歴、レイアウト変更は新しい座席表版で管理する。過去の座席位置・割当を再現できるようにする。
- 学校共通の時限の開始終了時刻、週時間割、座席表の変更は将来適用分として登録する。使用済みの内容を上書きせず、授業当時の日時・科目名・教員名・教室名・時限名・行事表示名を保持する。

## 6. 出席管理

### 6.1 区分・認定

| 出欠区分 | 判定 | 通常授業1時限の認定コマ |
|---|---|---:|
| 出席 | 開始から20分未満に参加し、途中退室しない | 1 |
| 遅刻 | 開始から20分以上で参加し、途中退室しない | 0 |
| 欠席 | 受講しない | 0 |
| 早退 | 途中退室・下校。遅刻と重なる場合も早退を優先 | 0 |
| 公欠 | 学校が出席相当と認めた欠席 | 1 |

20分ちょうどは遅刻とする。入退室の実時刻は保存せず、教職員が区分を判定する。コマ数は整数とし、0.5コマ等の部分認定は行わない。

### 6.2 事前連絡・候補表示

- 教職員が生徒・対象日・終日または時限を指定して、欠席・遅刻・早退・公欠等を事前登録する。未来日の登録を許可する。
- **同一生徒・同一日の終日連絡と時限指定連絡の共存、同一時限の重複連絡を禁止**する。異なる時限同士は共存できる。変更は旧連絡の削除・新規登録を一体で行う。
- 終日連絡は本人が履修する当日の対象授業へ適用し、日別変更後も該当授業へ反映する。事前連絡自体を確定出欠にしない。
- 初期表示は、**当該授業の保存済み出欠 → 該当する事前連絡 → 同日の直近HR・前時限の確定出欠 → 未登録**の順とする。未確定授業は継承元にしない。
- 継承時は次表で候補へ変換する。候補は表示用であり、表示・画面離脱・時間経過による保存は行わない。

| 継承元 | 出席 | 欠席 | 遅刻 | 早退 | 公欠 |
|---|---|---|---|---|---|
| 次時限の候補 | 出席 | 欠席 | 出席 | 欠席 | 公欠 |

### 6.3 確定・訂正

- 履修に基づく授業対象者を固定し、生徒・授業ごとに1件の出欠を持つ。席がないことを理由に対象者から外さない。
- 座席クリックで **出席 → 欠席 → 遅刻 → 早退 → 公欠 → 出席** と巡回する。区分選択と確定保存は別操作とする。
- 教職員が対象者全員の区分を確認し、一括して保存・確定する。対象者の不足・重複・余分な生徒を検出し、全員分と授業の確定日時を同時に保存する。
- **対象者が1人以上、全員分の出欠あり、授業の確定日時あり**を実施済みの条件とする。1人でも未確定なら、授業全体の総コマ・認定コマを集計しない。
- 全教職員が授業中・過去の出欠を訂正できる。訂正は現行値を更新し、集計へ反映する。訂正履歴の専用保存や、訂正のための時間割変更は行わない。
- 生徒は本人の当年度・過年度の履歴を閲覧できる。履修開始前はその旨を表示し、休学期間・履修開始前に欠席実績を自動作成しない。

## 7. コマ数・進級判定支援

### 7.1 集計と年度末基準

| 授業区分 | 実施済み総コマ | 認定出席コマ |
|---|---:|---|
| 通常授業・時間割上の行事 | 全員確定した1時限につき1 | 出席・公欠は1、その他は0 |
| 試験・HR | 0 | 0。出欠自体は管理可能 |
| 休校・休日・長期休暇 | 0 | 0。元の予定科目へ換算しない |

年度の総コマ数を固定値で持たず、生徒の履修対象である実施済み授業から科目別に集計する。休学前の実績は残し、休学期間は新規集計対象を作らない。

年度内の対象授業がすべて終了・確定した時点で、**`3 × 認定出席コマ数 ≥ 2 × 総授業コマ数`**なら科目の出席基準を満たす。表示用の丸め値では判定しない。実績0件は「実績なし」とし、基準達成にしない。進級・卒業の最終判断は教員が行う。

### 7.2 年度末の概算予測

`T`＝実施済み総コマ、`A`＝認定出席コマ、`Cᵢ`＝区分iの週当たり配置コマ、`Lᵢ`＝区分iの残り授業週数とする。

| 指標 | 算式 |
|---|---|
| 現在の出席ペース | `P = 100 × A / T` |
| 残り予測コマ | `F = Σ(Cᵢ × Lᵢ)` |
| 年度末総コマ見込み | `N = T + F` |
| 見込み必要認定コマ | `B = ceil(2N / 3)` |
| 残り必要認定コマ | `R = max(0, B − A)` |
| 残り必要出席率 | `Q = 100 × R / F` |
| 同ペース継続時の認定コマ見込み | `A + (P / 100) × F` |
| 残り欠席可能コマの目安 | `max(0, F − R)` |

- 学期・適用テンプレートが異なる区分は別々に計算して合算する。`ceil`は整数への切上げ。
- 残り授業週は整数とし、進行中の週と期間端の端数を含めない。長期休暇等の基準上の非授業週を除外し、実績との二重計上を防ぐ。
- **将来の日別振替・行事・臨時休校で予測値を補正しない**。実施後に実績として取り込み再計算する。
- `T = 0`ならP、`F = 0`ならQを「算出対象外」と表示する。設定漏れによる未計算と、計算結果の0を区別する。
- `T > 0`の現在ペースは`3A ≥ 2T`／`3A < 2T`、予測は`R > F`なら達成困難、`R ≤ F`なら達成見込みあり、`R = 0`なら見込み必要数達成と表示する。いずれも最終進級決定ではない。
- 生徒には本人の科目別実績・予測・根拠、教職員には対象者一覧・絞り込みを提供する。集計・予測値は元記録から算出し、実績として二重保存しない。

## 8. 成績管理

### 8.1 保存・公開・年間評価

- 生徒・学期・開講科目ごとに**0〜100点の評価点（小数可）**を保存する。試験ごとの得点・平常点内訳は管理しない。
- **未入力／保存済み**を区別し、保存済みの点数は公開・非公開を選択できる。未確定保存・再確定の状態は設けない。
- 公開中の点数を更新保存すると、生徒にも新しい値を表示する。非公開なら本人に表示しない。訂正通知は行わない。
- 年間平均は前後期履修なら2点の平均、片学期履修ならその点とする。必要な点数が欠ける間は「算出不可」。生徒への年間表示は、必要な点数がすべて保存・公開されてから行う。
- 年間評価は丸め前の平均点で判定し、学期ごとのA〜Dは付けない。

| 年間平均点 | 80以上 | 70以上80未満 | 60以上70未満 | 60未満 |
|---|---|---|---|---|
| 年間評価 | A | B | C | D |

- 「優・良・可・不可」は併記しない。Dの科目は注意表示する。
- 生徒は本人の当年度・過年度の公開成績を閲覧できる。教職員は科目・学期・生徒・点数・評価で検索・絞り込み・並べ替えできる。

### 8.2 統計

- 学期評価点は**同一年度・同一学期・同一科目**、年間平均点は**同一年度・同一科目**で集計する。教職員は保存済み点、生徒向けは公開済み点を対象とする。
- 平均`μ = Σxᵢ / n`、母集団標準偏差`σ = sqrt(Σ(xᵢ − μ)² / n)`、偏差値`50 + 10(x − μ) / σ`を用いる。
- 平均・偏差値は小数第2位まで表示する。表示丸めは年間評価・順位等の内部判定に使わない。
- 同点は競技順位方式（1位・1位・3位）。1人・全員同点でも平均と順位を表示し、`σ = 0`の偏差値は「算出不可」とする。
- 他生徒の個人別点数は公開せず、本人値と集計値だけを表示する。

## 9. 資格取得管理

- 教職員が資格名称一覧と、生徒・資格・受験回ごとの受験日、結果、取得日、有効期限、備考を管理する。生徒は本人分の閲覧のみ可能。
- 受験後の**結果待ち・不合格・合格**を扱う。再受験・更新・再取得は新しい記録を追加し、過去記録を残す。
- 結果待ちの有効期限区分は任意。合格・取得の確定時は、教職員による合格証等の現物確認、取得日、期限の有無を必須とする。有期限なら期限日も必須。
- 現物未確認の合格報告は結果待ちとして扱う。証明書ファイルは保存しない。
- 無期限は「無期限（有効）」、有期限は**期限当日まで有効、翌日から失効**と表示する。受験前の予定管理は行わない。

## 10. 就職活動・校内会場予約

### 10.1 企業・応募・選考

- 企業名・ふりがな・Webサイトと、実在する事業所・都道府県・所在地を登録・編集・参照する。生徒の希望勤務地は保存しない。
- 生徒は複数企業への応募を並行管理できる。同一企業への再応募は別案件とし、元の応募・選考履歴を保持する。
- 応募案件には企業別メモ、選考段階、進捗履歴を持つ。選考には予定日時・実施状態・結果・会場・質問回答・表示順を記録し、応募ごとの全選考を進捗ステップで表示する。
- 日程未定・結果未判明でも登録でき、順序は生徒が指定する。順序のために架空の日付を入れない。日時の一部しか判明していない情報は補足として保持し、確定日時と混同しない。
- 教職員は全生徒の進捗を参照し、生徒・企業・選考種別・個別結果・全体状態で検索・絞り込みできる。質問回答を他生徒へ公開しない。

| 分類 | 値・ルール |
|---|---|
| 選考種別 | 受験検討、会社説明会、書類選考、WEBテスト、筆記試験、1〜4次面接、最終面接、その他。その他は具体名必須 |
| 実施状態 | 予定／実施済み。延期は予定日時を変更 |
| 個別結果 | 未判明／通過／不通過／選考対象外。合否のない説明会等に選考対象外を使用 |
| 会場 | 自宅／企業／学校／その他／未定。必要に応じ詳細を記録 |
| 応募全体 | 検討中／応募済み／選考中／内々定／内定／不合格／辞退／中止 |

### 10.2 進捗の決定

応募全体の状態は、業務操作と選考結果からシステムが決定する。状態だけを直接編集する機能は設けず、矛盾する保存を拒否する。

| 業務上の事実・操作 | 反映 |
|---|---|
| 案件作成、応募前の検討活動 | 進捗履歴0件＝検討中。応募回数に含めない |
| 実際の応募を登録 | 応募済みの履歴を作成 |
| 応募後の選考が進行 | 選考中。個別の通過を内定とみなさない |
| 個別結果を登録 | 当該選考を実施済みに更新。合否対象との整合を検査 |
| 不通過による応募終了 | 不合格とし、残る未実施予定選考と対応予約を削除 |
| 内々定・内定の事実を登録 | 内々定／内定。内々定から内定へ移行可能 |
| 本人の辞退／応募先による中止 | 辞退／中止とし、未実施予定選考と対応予約を削除。実施済み記録は保持 |

不合格・辞退・中止の同一案件は再開しない。再応募は新しい案件として扱う。個別の未実施選考のみを取りやめる場合は、その選考と予約を削除する。検討をやめただけの場合は実応募の辞退履歴を作らない。

### 10.3 就活統計

- **応募数＝実際に応募した案件数**。同一企業への再応募も別件、検討中は0件とする。
- 内々定を内定数に含め、内々定から内定への移行は二重計上しない。現在内定数と、辞退済みも含む累計内定数を分ける。
- 比較集団は**同一コース／同一学科／同一クラス／同一学年（全学科）**から選択する。対象年度の現在在籍者を母集団とし、本人・応募0件を含め、卒業・退学・休学者を除外する。
- 同一学年は対象年度の同じ学年とする。本人値と、応募数・内定数の平均・中央値を並べて表示する。
- 本人値が**平均と中央値の両方を下回る場合のみ**注意表示する。ただし比較対象が1〜2人なら数値だけ表示し、注意表示を出さない。
- 教職員は応募数・内定数の並べ替え・絞り込み、支援対象者一覧を利用できる。

## 11. メール・帳票・履歴書・証明書

### 11.1 Gmail連携

- 教職員が対象生徒を選び、個別または**同一本文のBCC一括メール**を作成する。一括本文に個別氏名等を差し込まない。
- 宛先・件名・本文をURLでGmail作成画面へ渡し、利用者が確認・編集・送信する。通常の連絡にはシステム内の追加確認画面を設けない。
- URLが長すぎる等の場合は一括作成を中止して個別作成へ切り替える。BCC件数の固定上限は設けず、超過時は利用者が手動分割する。
- Gmailが開けない・ログインできない場合は案内と宛先・件名・本文のコピーを提供する。新規タブ等の開き方はGmail・ブラウザに従う。
- Gmail API等による自動送信、送信完了の取得、送信済み状態・履歴の保存は行わない。

### 11.2 PDF帳票

| 帳票 | 出力者 | 内容・条件 |

学校名・出力日を表示し、出力日を集計基準日とする。出席の任意期間実績と年度全体の予測は対象期間を明記する。未入力・実績・概算を区別し、文字化け・項目欠落・権限外出力を防ぐ。学校ロゴ・住所・電話の併記は必須としない。

- タイトル付きで履歴書を保存できる。氏名・生年月日・住所・連絡先等は学校登録情報から初期入力し、その後の履歴書側の編集内容を保持する。
- 写真、学歴・職歴・資格等の経歴、志望動機・自己PR・本人希望欄を入力・保存・再編集できる。写真・本文・経歴の未記入や途中保存を許容する。

### 11.4 証明書申請

- 成績証明書・卒業見込み証明書の申請文面を作成する。必須項目は**種類、提出先企業、必要部数、希望日、用途、学年、学科、コース、氏名**。

- 申請履歴・送信済み・受理状態は保存しない。訂正・再申請・取消は担当者へ直接連絡する。
- 担当者が受信内容を確認し、**受付時に手動でメール連絡**する。自動受付通知、発行進捗管理、証明書自体の自動発行は行わない。

## 12. データ整合性・非機能・運用

### 12.1 整合性・保持

- 学校日の参照は年間日程の日の識別子に統一し、対象日を一意にする。生年月日・受験日・有効期間・予約日時等の値は日付・時刻として扱う。
- 年度課程と学期の年度、開講科目と課程、履修と所属、変更元・先配置と対象課程、出欠と本人の履修、座席位置と座席表版、授業と座席表の教室を一致させる。行事も同じ授業・履修の整合規則に従う。
- 次の組合せを重複させない：**生徒＋学期、年度課程＋学期、年度課程＋科目、学期課程＋年度課程別科目、授業＋生徒、応募＋進捗記録順**。行事対象者は授業対象者として一意に管理する。
- 同時保存でも、期間・時間帯・座席・事前連絡・予約の禁止重複を防ぐ。DB制約と業務処理を併用し、画面上の入力制限だけに依存しない。
- 年度更新・異動・改名・時刻変更で過去記録の意味を変えない。削除・停止・非公開を別操作として扱う。
- 出席・成績・就活の集計値、出欠候補、Gmail文面、出席PDFの一時的な連絡事項は、元の実績と重複して保存しない。
