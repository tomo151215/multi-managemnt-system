# Git/GitHub使用方法

## 1. チーム開発の全体フロー
複数人で開発を行う場合、常に動作するベースコード（`main` ブランチ）を守りながら、機能ごとにブランチを作成して開発を進めます。

1. **最新コードの取得**: ローカルの`main` ブランチを頻繁にPullして常に最新状態にする
2. **作業ブランチ作成**: ローカルリポジトリで新規機能（新規ファイル）を作り始める際、機能ごとのブランチを生やす
   - ブランチの命名規則は`feature-{機能名}`に統一する
   - コマンドは`git switch -c feature-{機能名}`でブランチ作成とそのブランチへの移動を同時に行うことができる
3. **実装＆コミット**: コードを書いて変更を記録する
   - VScodeのGUIまたはGit Bashで`git add`、`git commit -m "commit-message"`を行い、**確実に動く範囲ごと**にコミットして万が一動かない場合に備えて、いつでも戻れるように保存していく。コミットメッセージは通常`update`や`remove`、`fix`などの接頭辞をつけるべきだが、今回は簡略化して無視する。
   - ***誰が読んでもコミットした内容がわかるようにしっかりとコミット内容を記述してください***
4. **リモートへ送信**: ブランチを GitHub に発行（Push）する
   - VScodeのブランチの発行でリモートリポジトリにブランチごとPUSHできる
   - 二度目以降は変更の同期ボタンにかわる
5. **プルリクエスト作成**: mainブランチに自分が作った機能（***必ず動作保証されている***）をmergeするためのレビュー依頼（PR:プルリクエスト）を出す
6. **コードレビュー**: メンバーがコードを確認（Approve）
7. **マージ**: `main` ブランチへ統合する



## 2. GitHubへのメンバー招待手順

チームメンバーをリポジトリに招待する際の手順です。

### 招待する側（管理者）の手順
1. GitHub で対象のリポジトリページを開く
2. 上部メニューの **「Settings（歯車アイコン）」** をクリック
3. 左サイドバー **「Access」** ＞ **「Collaborators」** を選択
4. **「Add people」** ボタンをクリックし、相手の GitHub ユーザー名 または メールアドレス を入力して招待を送信

### 招待された側（メンバー）の手順
1. GitHub から届く招待メールを開き、**「Accept invitation」** をクリックする  
   （※メールがない場合は `https://github.com/[管理者ユーザー名]/[リポジトリ名]/invitations` に直接アクセスして承諾）

## 3. ブランチ保護設定（管理者がマージを管理する設定）

「勝手に `main` にマージされるのを防ぎたい」「承認（Approve）を受けたコードだけを取り込みたい」場合の設定手順です。

1. リポジトリの **「Settings」** ＞ 左メニューの **「Branches」** を開く
2. **「Branch protection rules」** の **「Add branch protection rule」** をクリック
3. **Branch name pattern** に `main` を入力
4. **`Require a pull request before merging`** にチェックを入れる
   - **`Require approvals`** にチェックを入れ、必要な承認数（例: `1`）を指定
5. 画面下の **「Save changes」** をクリックして保存

> 💡 **ポイント**  
> 書き込み権限を持つメンバーでも、指定人数の Approve を得るまでマージ不可になります。リポジトリ管理者（Admin）は最終確認を行ってマージを実行します。

## 4. VS CodeでGit/GitHubを使用する方法

### (1) 変更ファイルの確認
1. `Ctrl` + `Shift` + `G`（Mac: `Cmd` + `Shift` + `G`）で「ソース管理」を開く
2. Gitディレクトリのあるフォルダ（ローカルリポジトリ）内で変更がある場合、「変更」タブに変更されたファイルが表示される

   - **ファイル状態の記号**
     | アルファベット | 単語 | 意味 |
     | :--- | :--- | :--- |
     | **A** | Added | 新規追加 |
     | **M** | Modified | 変更あり |
     | **U** | Untracked | Git未追跡（新規作成、add前） |
     | **D** | Deleted | 削除済み |
     | **C** | Conflict | コンフリクト発生中 |
     | **R** | Renamed | ファイル名変更済み |
     | **S** | Submodule | サブモジュール |

### (2) ステージングとコミット
1. **ステージング（`git add` 相当）**
   - 変更ファイルの右側にある **`+`（ステージング）** ボタンをクリックする（全体の変更をまとめて登録する場合は親見出しの `+` をクリック）
2. **コミット（`git commit` 相当）**
   - メッセージ入力欄に何を変更したかを入力（例: `ログイン画面のUIを追加`）
   - **「コミット」** ボタンを押す

### (3) ブランチの作成と切り替え
1. VS Code 左下の「現在のブランチ名」をクリック（または `Ctrl` + `Shift` + `P` ＞ `Git: Create Branch...`）
2. メニューから **「新しいブランチを作成...」** を選択
3. ブランチ名（例: `feature/login-page`）を入力して `Enter`

### (4) リモートへの送信（ブランチを発行）
1. 作成したブランチを初めて GitHub に送る場合は **「ブランチを発行」** ボタンを押す  
   （※内部で `git push -u origin <ブランチ名>` が実行され、GitHub上に同一ブランチが作成される）
2. 2回目以降の変更送信は **「変更の同期」** ボタンで行う

## 5. プルリクエスト（PR）とレビューの流れ

### (1) プルリクエストの作成（作業者）
1. ブランチを発行後、GitHub のリポジトリページを開く
2. 画面上部に表示される **「Compare & pull request」** ボタンをクリック
3. **タイトル・説明文・レビュアー** を設定し、**「Create pull request」** を送信

### (2) コードレビューとApprove（レビュアー）
1. PR画面の **「Files changed」** タブを開き、変更差分を確認する
2. 右上の **「Review changes」** ボタンをクリック
3. コメントを入力し、**`Approve`** を選択して **「Submit review」** を送信する

### (3) マージと後処理（作業者 / 管理者）
1. 承認（Approve）を確認したら、PR画面下部の **「Merge pull request」** ＞ **「Confirm merge」** を押す
2. **「Delete branch」** ボタンを押し、不要になったリモートブランチを削除する
3. 自分のローカルで `main` に切り替え、最新化する
   ```bash
   git checkout main
   git pull origin main
